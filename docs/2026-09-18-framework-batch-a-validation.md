## 1. 实现结果

- 启动脚本从自身位置定位仓库，显式配置错误立即失败；共享命令包装检查原生命令退出码。CMake configure/build 失败不运行旧 EXE。
- 统一入口核对依赖准备记录、端口、数据库、本次服务身份及就绪状态；前端启用 strictPort，Python 固定单 worker。
- 日志保存在 logs/startup/<launch_id>，成功后生成进程启动记录；stop-all 核对 PID、创建时间和映像后停止对应服务。失败清理仅处理持续持有句柄或核实父子创建时间的进程，归属不明则警告并保留。
- npm ci 与 uv sync --locked 移入显式准备入口，记录工具版本和输入摘要。准备失败不会保留上一轮有效准备记录；日常启动不自动安装。
- 公共 CMake 通过 VCPKG_ROOT 找工具链，默认依赖安装位于构建目录；已有不同工具链/依赖目录的缓存要求新目录或明确本机预设。构建、启动和测试均按显式目录及配置选产物。
- C++ 每次构建检查源码输入，将 build_id/source_digest/configuration 等嵌入二进制，成功链接后发布同源清单。Python 在启动时固定摘要；健康请求不重新读取磁盘或 Git。
- 原审查第 11 条已修复。P2 第 5～10 条及其他业务重构未纳入本次修改。

应用数据库连接来自 ConfigPath.postgres。BRIDGE_REPORT_DATABASE_URL 仅在既有维护入口受支持，启动器明确拒绝，避免检查与服务连接到不同目标。隔离回归使用成对的 BRIDGE_REPORT_TEST_DATABASE_URL/BRIDGE_REPORT_TEST_SCHEMA。
