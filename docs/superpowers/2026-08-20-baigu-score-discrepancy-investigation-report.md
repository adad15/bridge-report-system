## 4. 问题一：“熏黑痕迹”被非评分节点排除

### 4.1 报告中的原始记录

报告上部结构病害表中包含以下记录：

| 构件范围 | 病害位置 | 病害描述 | 报告标度 |
| --- | --- | --- | ---: |
| `1-1#板～1-25#板` | 板底 | 存在熏黑痕迹 | 2 |
| `2-1#板～2-25#板` | 板底 | 存在熏黑痕迹 | `/` |

报告的上部承重构件评分为81.54。从分数反推可以确认，第一个25块板范围按标度2参与了报告计分，第二个范围未计分。

### 4.2 系统中的实际处理

系统已将两个范围分别拆成25个实际构件，但它们被映射到“上部其它病害”节点。该节点的评分模式是 `non_scoring`，且拆分后数据中：

- `defect_scale = null`；
- `standard_defect_indicator_id = null`；
- 25个第一跨候选均被记录为 `rating_tree_non_scoring`；
- 25个第二跨候选也被排除，但这与报告的`/`标度一致，不造成本次分差。

当评定树节点为 `non_scoring` 时，服务端会直接将病害记入跳过清单，不将其送入 H21 评分器。对应实现位于：

- `backend-cpp/src/assessment/AssessmentService.cpp:333`
- `backend-cpp/src/assessment/AssessmentService.cpp:340`

### 4.3 分数复算

系统当前上部承重构件的关键中间值：

| 参数 | 值 |
| --- | ---: |
| 构件数 $n$ | 825 |
| 构件平均分 | 98.9151515 |
| 最低构件分 | 65.0000000 |
| 构件数量系数 $t$ | 2.3 |
| 系统部件分 | 83.6977602 |

如果按报告口径让25块第一跨板参与标度2评分：

- 其中24块由100分降为75分；
- `1-25#板`原已有一项25分扣分，增加同级扣分后构件分变为61.7417479；
- 新的构件平均分为98.1718082；
- 新的最低构件分为61.7417479。

按部件评分公式：

$$
PCCI = \bar{S} - \frac{100-S_{min}}{t}
$$

得：

$$
98.1718082 - \frac{100-61.7417479}{2.3}
= 81.5377855 \approx 81.54
$$

复算结果与报告完全一致。进一步按上部结构权重0.70、0.18、0.12计算，上部结构分也从85.60回到84.09。

### 4.4 根因定性

> [!bug] 根因
> 报告生成软件对“上部其它病害”使用了可扣分的单位扩展口径，而本系统评定树2.0按设计要求将没有 H21 评分依据的“其它病害”设为非评分节点。这是评分政策不同，同时也暴露了导入后页面未显著告知“该范围将不扣分”的交互风险。

### 4.5 影响

- 上部承重构件高估2.16分。
- 上部结构高估1.51分。
- 全桥高估约0.61分。
- 所有选择“其它病害”的历史试算均可能出现类似偏高，但是否应扣分属于业务政策决策，不能直接将其映射到不相关的 H21 官方指标。

### 5.2 系统绑定

- 构件：左侧栏杆；

- 标度：3；

- 右侧构件分：100。

该病害的 `component_match_method` 为 `manual`，说明问题发生在构件人工选择或范围处理阶段，不是 H21 扣分值错误。

### 5.3 分数复算

系统当前对两个栏杆构件的处理：

$$
\bar{S}=\frac{60+100}{2}=80,\quad S_{min}=60,\quad t=10
$$

$$
PCCI=80-\frac{100-60}{10}=76
$$

报告将“两侧护栏”同时作用到两个构件：

$$
\bar{S}=\frac{60+60}{2}=60,\quad S_{min}=60,\quad t=10
$$

$$
PCCI=60-\frac{100-60}{10}=56
$$

结果恰好复现报告中的56.00分。

### 5.4 根因与影响

> [!bug] 根因
> “两侧护栏”是语义上明确的多构件范围，但导入草稿没有将它拆分成左、右两个病害候选，人工绑定又只选择了左侧栏杆，导致右侧被当作无病害100分。

影响链：

1. 栏杆、护栏部件高估20分；
2. 该部件在桥面系内的权重为0.10，桥面系高估2分；
3. 桥面系在全桥权重为0.20，全桥高估**0.40分**。

## 7. 问题四：下部结构权重和报告分数无法相互复现

### 7.1 报告公开数据

报告列出的下部结构原始权重为：

| 部件 | 部件分 | 原始权重 | 报告“重新分配后权重” |
| --- | ---: | ---: | ---: |
| 翼墙、耳墙 | 100.00 | 0.02 | 0.02 |
| 锥坡、护坡 | 100.00 | 0.01 | 0.01 |
| 桥墩 | 78.41 | 0.30 | 0.31 |
| 桥台 | 87.89 | 0.30 | **`4`（异常）** |
| 墩台基础 | 100.00 | 0.28 | 0.29 |
| 河床 | 100.00 | 0.07 | 0.07 |
| 调治构造物 | 无 | 0.02 | `/` |

调治构造物缺失后，现有部件的原始权重合计为0.98。报告的桥台重新分配权重单元格在 Word XML 中实际文本就是`4`，不是提取程序丢失小数点。

### 7.2 系统权重处理

系统对存在的部件执行精确比例归一化：

| 部件 | 系统有效权重 |
| --- | ---: |
| 翼墙、耳墙 | 0.02040816 |
| 锥坡、护坡 | 0.01020408 |
| 桥墩 | 0.30612245 |
| 桥台 | 0.30612245 |
| 墩台基础 | 0.28571429 |
| 河床 | 0.07142857 |

计算结果为：

$$
\frac{
100\times0.02+100\times0.01+78.41\times0.30
+87.89\times0.30+100\times0.28+100\times0.07
}{0.98}
=89.6836735
$$

使用系统未四舍五入的部件分计算得到89.6857441，页面显示为89.69。

### 7.3 异常判断

报告公布的部件分和原始权重按比例归一化后得到89.68左右，不能复现报告中的89.55。由于报告同时存在桥台权重`4`这一明显异常，当前只能得出以下结论：

1. 系统89.69符合现有部件权重按比例重新分配的算术结果；
2. 报告89.55使用了未在报告中完整公开的内部精度、特殊权重分配或旧版中间结果；
3. 也不能排除报告模板或来源软件存在计算/输出错误；
4. 在没有来源软件该任务的完整中间评分轨迹前，无法唯一确定89.55的内部算法。

> [!warning] 不建议的做法
> 不应为了将结果硬对齐89.55而在系统中增加未有规范依据的“百股大桥特例权重”或调整四舍五入顺序。

- 确认实际是“完好”还是“局部排水不畅”；
- 如果按 H21 “排水不畅”评分，标度1对应100分，标度2对应的扣分为25而不是20；
- 如果必须得到报告的80分，则需先确认报告使用的是哪个单位扩展指标及其扣分表，不应将80分硬写成 H21 “排水不畅”的结果。

#### C. 核实锥坡、护坡台账

- 确认规范评价构件口径是“左右侧分开”还是“每桥台一件”；
- 确认锥坡与护坡是独立构件还是同一评价构件的现场名称；
- 修正生成向导或该桥台账，并对其他桥梁执行数量回归。

### 11.2 需业务决策的评分政策

#### “其它病害”是否参与自主评分

建议在以下两种模式中明确选择，不应通过隐式映射混用：

**模式1：规范严格模式**

- 仅 H21 有明确指标、标度和扣分依据的病害参与评分；
- “熏黑痕迹”保留为记录，但不扣分；
- 系统84.42不必与来源报告82.96完全一致；
- 页面必须明确标识非评分病害及影响。

**模式2：单位扩展兼容模式**

- 为来源软件的“上部其它病害”建立显式、可版本化的单位扩展评分规则；
- 规则必须记录来源、适用范围、允许标度和扣分值；
- 不得冒充 H21 官方指标；
- 对第一跨25块板按标度2计分后，上部承重构件可复现81.54。

### 11.3 报告对账策略

- 将“来源报告分”与“系统自主评分”分开展示；
- 增加结构、部件、病害三层差异树；
- 对下列差异给出机器可读的原因码：
  - `non_scoring_defect_excluded`；
  - `component_scope_mismatch`；
  - `scale_mismatch`；
  - `component_count_mismatch`；
  - `weight_reallocation_mismatch`；
  - `source_result_not_reproducible`。
- 不以“强制系统总分等于报告总分”作为单一验收条件，而应以每一层输入和中间值可解释为验收依据。

## 14. 验收标准

### 14.1 如采用“规范严格模式”

1. 系统继续不对“熏黑痕迹”扣分，但试算页明确披露该项对报告对账的影响。
2. “两侧护栏”必须作用到左右两个构件。
3. 防排水系统按复核后的 H21 指标和标度评分。
4. 系统分不必强制等于82.96，但每个差异必须有明确原因。

### 14.2 如采用“单位扩展兼容模式”

1. “熏黑痕迹”的扩展指标、标度和扣分规则有独立 ID、版本、来源和轨迹。
2. 第一跨25块板参与评分后，上部承重构件为81.54，上部结构为84.09。
3. 左右护栏均参与后，栏杆、护栏为56.00。
4. 防排水系统只有在扣分规则受控、可溯源时才能采用80.00。
5. 下部结枉.55仍需要来源软件轨迹支持，不允许通过桥梁特例逻辑伪造对齐。

## 15. 最终结论

1. 系统84.42的分层汇总算术正确，可以由系统快照精确复现。
2. 与报告82.96的1.46分差值中，约1.41分可由三项病害输入/绑定差异解释：
   - “熏黑痕迹”未计分：约0.61分；
   - “两侧护栏”只绑左侧：0.40分；
   - 防排水标度/指标差异：0.40分。
3. 剩余0.05分来自下部结构口径差异。报告中桥台重新分配权重为异常值`4`，且89.55无法由报告公开的部件分和权重复现。
4. 参评构件数还存在5174与5172的差异，虽未影响本次分数，但应在正式评定前处理。
5. 本次问题的正确处理方式是让病害范围、指标、标度、构件清单和评分政策全部可解释，而不是在最终总分处增加补偿值。

> 在将本次试算确认为正式评定前，至少应完成左右护栏绑定修正、防排水标度复核和“其它病害”评分政策确认。下部结构89.55如仍作为对账基准，还必须补充来源软件的计分轨迹或人工签字确认差异。
