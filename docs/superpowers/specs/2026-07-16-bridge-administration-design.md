# 模块 06.5 补充设计：管理员新增与批量永久删除桥梁档案

> 日期：2026-07-16
>
> 状态：设计已确认，等待用户复核
>
> 关联设计：
> - `docs/superpowers/specs/modules/06-5-bridge-centric-interaction-redesign.md`
> - `docs/superpowers/specs/modules/06-5-admin-delete-inspection-year.md`

## 1. 背景与目标

当前桥梁档案页只能搜索和进入已有桥梁，没有新增入口；桥梁数据通常依赖数据库脚本提前创建，也不能由管理员清理误建桥梁。本功能把桥梁档案页补齐为管理员维护入口：管理员可以用精简表单新增桥梁，并通过复选框选择一座或多座桥梁进行永久删除；普通用户继续保持只读。

桥梁删除采用整桥语义。成功删除一座桥时，该桥全部年度版本、导入记录、校对草稿、构件、病害、尺寸、照片关系、评分、病害线索、病害对比、别名和独占归档文件都进入删除范围。删除不可恢复，因此必须具备实时影响预览、精确确认、活动编辑锁阻断、影响令牌、单桥原子事务、永久审计和持久文件清理队列。

批量操作采用“逐座独立事务”：同一批次内能安全删除的桥正常删除；存在编辑锁、影响变化或数据库错误的桥保留，并在结果中逐座说明原因。

## 2. 已确认决策

1. 只有管理员可以新增或删除桥梁；普通用户看不到入口，后端仍独立鉴权。
2. 桥梁列表顶部相邻放置“添加桥梁”和“删除选中桥梁”按钮。
3. 表格首列使用复选框，允许选择多座桥；不在每行单独放删除按钮。
4. 表头复选框只选择当前搜索结果；搜索条件改变时清空全部选择，避免隐藏选中项。
5. 新增桥梁采用精简表单，系统编号由后端生成。
6. “桥名 + 路线编号 + 桩号”完全相同视为重复；同名但路线或桩号不同允许创建。
7. 单选确认文字为 `永久删除 QL-001287`；多选确认文字为按系统编号升序拼接的 `永久删除 QL-001287、QL-001288`。
8. 一批桥梁逐座独立提交，一座失败不回滚已经成功删除的其他桥。
9. 任一目标桥存在有效编辑锁时，只阻止该桥；删除接口不能隐式强制解锁。
10. 桥梁业务数据永久删除且不可恢复；删除行为的元数据、原因和数量审计永久保留。
11. 以前的年度删除审计继续保留，其 `bridge_id` 在桥梁删除后按既有外键置空，桥梁快照仍可查。
12. 数据库事务提交后才允许删除物理文件；文件失败不代表业务数据只删除一半。
13. 文件队列在删除后立即、后端启动时和运行期间每 5 分钟重试。
14. 第一版不新增删除审计查询页面，也不新增桥梁基本信息编辑页面。

## 3. 非目标

1. 不提供桥梁回收站、撤销删除或恢复。
2. 不提供普通用户的删除申请、审批流或临时授权。
3. 不在本功能中新增完整桥梁信息编辑页。
4. 不在新增弹窗中维护经纬度、桥型、跨径、桥长、桥宽、建成年份和养护单位。
5. 不重新设计模块 07 病害对比业务；只删除属于目标桥梁的现有对比数据。
6. 不把桥梁删除转换为后台长任务；数据库删除仍在请求内逐座完成。

## 4. 权限与桥梁列表交互

### 4.1 顶部操作区

管理员看到：

```text
桥梁档案                           ＋ 添加桥梁   删除选中桥梁（2）
```

普通用户不渲染这两个按钮和表格复选框。未选择桥梁时“删除选中桥梁”禁用；选择后按钮显示数量。

### 4.2 表格选择

管理员表格布局：

```text
☐  系统编号    桥名          路线       状态   最新结论   待办
☐  QL-001287   绕阳河二号桥   S213库盘线  在用      —       —
☐  QL-001288   测试桥        G305       在用      —       —
```

- 点击复选框只改变选择，不触发行导航；
- 点击行的其他区域仍进入桥梁概览；
- 表头复选框选择或取消当前可见搜索结果；
- 搜索文本发生变化时清空选择；
- 数据刷新后，已经不存在的桥梁 ID 从选择中移除。

## 5. 新增桥梁

### 5.1 表单字段

- 桥梁名称：必填；
- 路线编号：选填，例如 `S213`；
- 路线名称：选填，例如“库盘线”；
- 行政区划：选填；
- 桩号：选填；
- 状态：`在用`、`停用`、`拆除`，默认 `在用`；
- 系统编号：不允许前端填写，由数据库生成。

所有文本在后端去除首尾空白。空的选填文本写为 `NULL`，不保存空字符串。

### 5.2 重复判定与并发

重复身份键由规范化后的桥名、路线编号和桩号组成。比较时忽略首尾空白和英文字母大小写，`NULL` 与空字符串等价。后端在新增事务内按该规范键取得事务级 PostgreSQL advisory lock，再查询现有桥梁并插入，保证两个并发请求不能同时创建相同桥梁。

重复时返回 409 和现有桥梁 ID、系统编号、名称；前端提示“该桥梁已经存在”并提供进入已有桥梁的操作。同名但路线编号或桩号不同不视为重复。

### 5.3 创建成功

创建成功返回新桥梁摘要，前端关闭弹窗并进入新桥梁概览。新桥没有年度时显示既有空状态，管理员可继续创建年度检测。

## 6. 批量删除交互

### 6.1 实时影响预览

点击“删除选中桥梁”后，前端把所选桥梁 ID 发送给后端。加载完成前不显示可提交表单。弹窗按系统编号排序显示每座桥：

- 系统编号、桥名、路线、桩号和状态；
- 年度数、年度版本数、导入记录数；
- 构件、桥梁别名、构件别名；
- 病害观测、尺寸、正式照片、评分；
- 病害线索和病害对比；
- 独占归档文件和共享保留文件；
- 活动编辑锁的编辑人、年度和到期时间。

弹窗同时显示整批合计。任何响应均不得返回文件 ID、相对路径或绝对路径。

### 6.2 提交门槛

管理员必须：

1. 填写统一的非空删除原因；
2. 准确输入后端返回的确认文字；
3. 等待影响预览加载完成。

存在活动锁的桥在预览中标记为“本次不能删除”，但不会阻止同批其他桥提交。确认文字仍包含全部所选桥梁编号，因为提交结果必须明确报告锁定桥没有删除。提交期间禁止关闭弹窗和重复提交。

### 6.3 逐座结果

结果分为“已删除”和“未删除”：

```text
已删除 2 座

✓ QL-001287 绕阳河二号桥
  年度 3 · 构件 28 · 病害 80 · 文件 120

✓ QL-001289 测试桥
  桥梁业务档案已完整删除；2 个孤立归档文件等待后台清理

未删除 1 座

✗ QL-001288 辽河桥
  张工正在编辑 2026 年度，请先退出校对或解除编辑锁
```

成功桥梁从列表移除；失败桥梁保留。结果显示后清空本批选择，关闭弹窗时重新加载桥梁列表。

## 7. API 合同

### 7.1 新增桥梁

```http
POST /api/bridges
Content-Type: application/json

{
  "bridge_name": "绕阳河二号桥",
  "route_number": "S213",
  "route_name": "库盘线",
  "administrative_region": "黑山县",
  "station_mark": "K123+456",
  "status": "在用"
}
```

要求登录且角色为管理员。成功返回 201 和桥梁摘要。重复返回 409：

```json
{
  "code": "bridge_already_exists",
  "message": "相同桥名、路线编号和桩号的桥梁已经存在。",
  "existing_bridge": {
    "id": "...",
    "system_number": "QL-001287",
    "bridge_name": "绕阳河二号桥"
  }
}
```

### 7.2 批量影响预览

```http
POST /api/bridges/deletion-impact
Content-Type: application/json

{
  "bridge_ids": ["...", "..."]
}
```

要求管理员。桥梁 ID 去重，单次最多 100 座。成功响应包含按系统编号排序的 `bridges[]`、每座桥的 `impact_token`、`totals` 和 `confirmation_text`。

影响预览属于尚未开始删除的批次级校验。只要任一所选桥梁已经不存在，整个预览返回 409 `bridge_selection_changed`，不生成部分预览；前端提示列表已经变化，清空选择并重新加载桥梁列表。这样确认文字不会悄悄遗漏用户原先选中的桥梁。

### 7.3 批量永久删除

```http
DELETE /api/bridges
Content-Type: application/json

{
  "reason": "误建测试桥梁",
  "confirmation_text": "永久删除 QL-001287、QL-001288",
  "items": [
    {"bridge_id": "...", "impact_token": "sha256:..."},
    {"bridge_id": "...", "impact_token": "sha256:..."}
  ]
}
```

后端必须重新按桥梁系统编号排序并生成确认文字，不信任前端顺序。通过批次级请求校验后，逐座调用独立删除事务。

成功 HTTP 响应表示批次已处理完成，不表示每座桥都删除成功：

```json
{
  "batch_id": "...",
  "results": [
    {
      "bridge_id": "...",
      "system_number": "QL-001287",
      "bridge_name": "绕阳河二号桥",
      "status": "deleted",
      "file_cleanup_status": "completed",
      "pending_file_count": 0,
      "audit_id": "..."
    },
    {
      "bridge_id": "...",
      "system_number": "QL-001288",
      "bridge_name": "辽河桥",
      "status": "locked",
      "message": "张工正在编辑 2026 年度"
    }
  ]
}
```

### 7.4 稳定错误语义

批次级错误使用 HTTP 状态码并且整批不开始：

- `auth_required`：未登录，401；
- `forbidden`：普通用户，403；
- `invalid_bridge_request`：新增字段无效，400；
- `bridge_already_exists`：重复桥梁，409；
- `invalid_bridge_selection`：ID 为空、非法、重复规范化失败或超过 100 座，400；
- `bridge_selection_changed`：预览时任一所选桥梁已不存在，409；
- `invalid_bridge_deletion_request`：原因、确认文字或令牌结构无效，400。

进入逐座处理后的业务结果放入 `results[]`，不把整批变成 HTTP 错误：

- `deleted`；
- `locked`；
- `impact_changed`；
- `not_found`；
- `failed`。

`failed` 只返回中性说明和稳定错误码，不向前端暴露 SQL、路径或服务端异常文本。

## 8. 影响计划与并发控制

每座桥的规范影响计划按稳定顺序包含：桥梁主记录及 `updated_at`、全部年度版本、导入记录、桥梁别名、构件、构件别名、病害、尺寸、照片、评分、线索、对比、候选文件分类和活动编辑锁。计划编码为规范 JSON 后计算 SHA-256。

影响令牌只检测预览后的数据变化，不承担授权作用。单桥删除事务内：

1. `FOR UPDATE` 锁定桥梁；
2. 锁定目标年度、导入记录、事实数据和候选归档文件；
3. 重新构造影响计划；
4. 影响令牌不一致则回滚并返回 `impact_changed`；
5. 再次检查 `expires_at > now()` 的活动编辑锁；
6. 有锁则回滚并返回 `locked`；
7. 无冲突才写审计并执行删除。

每座桥使用独立事务和提交结果；批次循环不得复用一个跨桥数据库事务。

## 9. 数据删除边界与顺序

单桥事务显式删除：

1. 引用目标桥年度或观测的病害对比；
2. 目标桥导入记录、导入文件关联、编辑锁和锁事件；
3. 目标桥年度的病害尺寸、正式照片、病害观测和评分；
4. 全部年度版本及修订引用；
5. 病害线索、桥梁构件、构件别名和桥梁别名；
6. 已确认没有桥外引用的候选 `archived_files` 元数据；
7. `bridges` 主记录。

事务提交前写入整桥删除审计和待清理文件清单。数据库外键仍作为最后保护：发现未纳入计划的新桥级表时让事务失败回滚，不能静默遗留孤儿数据。

共享文件判定必须检查全部现有文件引用。仍被其他桥梁或系统数据引用的文件保留；其目标桥关系按外键解除或在事务内显式清空。以前的 `inspection_year_deletion_audits` 不删除。

## 10. 删除审计

新增 `bridge_deletion_audits`：

- `id`、审计系统编号、`batch_id`；
- 可空 `bridge_id`，外键明确使用 `REFERENCES bridges(id) ON DELETE SET NULL`；以及桥梁编号、名称、路线、桩号、状态快照；
- 操作用户 ID、用户名和显示名快照；
- 删除原因；
- 影响计划公共快照和删除数量 JSON；
- 文件清理状态、创建时间和清理完成时间。

审计不保留病害正文、评分明细、Word、照片、草稿或原始 JSON，不能用于恢复桥梁。每座成功删除的桥写一条审计，同一批次通过 `batch_id` 关联。锁定、影响变化和数据库失败不会伪造“删除成功”审计。

审计在删除桥梁主记录前插入；同一事务删除 `bridges` 后，`bridge_id` 自动置空。审计查询和追责只依赖永久快照，不依赖已经删除的桥梁主表。以前的 `inspection_year_deletion_audits` 采用相同的快照保留原则。

## 11. 文件清理与持续重试

桥梁删除使用独立且有审计外键的桥梁文件清理队列表；年度删除队列表继续保留。两者共用安全路径解析和物理删除核心，由统一 `ArchiveFileCleanupCoordinator` 调度。

桥梁队列表至少保存：所属删除审计 ID、待删除文件的受控标识、状态、尝试次数、最近错误、`next_attempt_at`、`processing_started_at`、创建时间和完成时间。状态统一为 `待清理`、`清理中`、`失败待重试`、`已完成`。年度删除现有队列通过迁移补齐相同的领取与重试字段和“清理中”状态，原有记录保持兼容：未完成记录继续可领取，已完成记录不重新执行。

“清理中”的恢复时限采用后端配置并提供安全默认值；每 5 分钟是调度频率，不等于失败项必须每 5 分钟重试。失败项按 `next_attempt_at` 和有上限的退避策略领取，避免持续占用或权限错误造成热循环。首次实现必须给退避参数和恢复时限写自动化测试，不能只留作运行约定。

清理时序：

1. 数据库提交后立即尝试本批文件；
2. 后端启动时处理遗留项目；
3. 后端运行期间每 5 分钟处理一次；
4. 每批有数量上限，避免长时间阻塞；
5. 使用 `FOR UPDATE SKIP LOCKED` 领取并标记“清理中”；
6. 同一项目不能被立即、启动和定时清理器重复领取；
7. 进程异常留下且超过恢复时限的“清理中”项目重新进入待重试；
8. 文件不存在视为幂等成功；
9. 失败保存错误、尝试次数和下一次重试时间；
10. 全部完成后更新所属删除审计。

业务删除状态始终为 `deleted`。文件未完成只通过 `file_cleanup_status: pending` 和 `pending_file_count` 表达，前端文案必须说明“业务档案已完整删除，孤立文件等待清理”。

## 12. 组件边界

### 12.1 后端

- `BridgeAdministrationRoutes`：鉴权、请求解析、批次级校验和响应脱敏；
- `BridgeAdministrationRepository`：并发安全新增桥梁与重复检查；
- `BridgeDeletionPlanner`：纯影响计划、计数、共享文件分类和令牌；
- `BridgeDeletionRepository`：单桥锁定、复核、审计和原子删除；
- `ArchiveFileDeletionCore`：安全路径解析和单文件幂等删除；
- `ArchiveFileCleanupCoordinator`：立即、启动、定时、有界领取和异常恢复。

高风险删除逻辑不加入现有 `ReviewRepository` 或 `WorkspaceRepository`。

### 12.2 前端

- `CreateBridgeDialog`：精简表单、重复桥提示和创建后导航；
- `DeleteBridgesDialog`：影响预览、原因、确认文字、提交和逐座结果；
- `BridgesPage`：管理员按钮、选择状态、搜索变化清空和列表刷新；
- 独立桥梁管理 API 模块：新增、批量预览和批量删除类型及请求。

## 13. 测试与验收

### 13.1 新增桥梁

1. 未登录 401、普通用户 403、管理员成功；
2. 必填、长度、状态和空白规范化；
3. 系统编号由数据库生成；
4. 同桥名、同路线编号、同桩号返回已有桥；
5. 同名但路线或桩号不同允许创建；
6. 两个并发相同请求只能插入一条；
7. 创建成功进入无年度的桥梁概览。

### 13.2 列表与弹窗

1. 普通用户无按钮和复选框；
2. 管理员按钮相邻显示；
3. 未选择时删除禁用，数量正确；
4. 表头只选择当前搜索结果；
5. 搜索变化清空选择；
6. 复选框不触发行导航；
7. 预览逐桥计数与总计正确；
8. 确认编号完整且顺序严格；
9. 提交期间防关闭和重复；
10. 逐座成功/失败结果与列表刷新正确。

### 13.3 删除事务

1. 单座桥全部年度 V1/V2 一次删除；
2. 导入、草稿、编辑锁、构件、别名、病害、尺寸、照片、评分、线索和对比删除；
3. 独占文件元数据删除，共享文件保留；
4. 以前的年度删除审计保留；
5. 活动锁返回 `locked` 且目标桥无变化；
6. 旧影响令牌返回 `impact_changed`；
7. SQL 失败时单桥事务完整回滚；
8. 同批两座成功、一座锁定时只保留锁定桥；
9. 每座成功桥产生审计且共享 `batch_id`；
10. API 不泄漏文件路径或 SQL 异常。

### 13.4 文件清理

## 14. 风险控制

1. **误删整桥**：管理员限定、复选框、实时逐桥预览、原因和全部系统编号精确确认。
2. **批量结果误解**：逐座独立结果，不用一个模糊的整批成功提示。
3. **正在校对时删除**：活动锁只阻断对应桥，删除接口不隐式强制解锁。
4. **预览后变化**：每座桥独立影响令牌和事务内重新计算。
5. **半桥数据库状态**：单桥原子事务，任何数据库错误完整回滚该桥。
6. **数据库与磁盘不一致**：先提交数据库，再清理孤立文件；业务删除和磁盘清理状态分开表达。
7. **清理队列无人处理**：立即、启动和每 5 分钟持续重试，使用持久状态、领取锁和异常恢复。
8. **共享文件误删**：锁定候选文件并复核全部外部引用，只删除独占文件。
9. **重复建桥**：规范身份键 advisory lock 和事务内二次查询。
10. **未来新增桥级表遗漏**：显式计划配合外键保护和集成测试，遗漏时删除失败回滚而不是留下孤儿。
