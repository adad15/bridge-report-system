# 病害与照片两阶段校对设计

## 1. 背景

“病害与照片”页面目前以完整病害卡片为基本单位。每张卡片同时展示Word原文字段、正式病害字段、校对状态、照片编号、测量信息、备注和照片维护区。

这套布局适合查看单条病害，但当前导入记录已有数百条病害，暴露出两个核心问题：

1. 用户必须逐条展开、逐条确认，正常导入项也消耗大量操作时间；
2. 原文证据、正式档案字段和照片关系处于同一视觉层级，精细维护时难以判断哪个字段参与评定、哪个字段只是原始证据。

页面的目标不是单纯压缩卡片，而是支持连续的两个阶段：

1. 用户进入页面后快速判断整体导入质量，批量确认明确正常的病害；
2. 用户继续处理异常项，并精细维护可入库、可评分、可追溯的病害档案。

## 2. 设计目标

- 数百条病害中，正常项不再要求逐条手工确认；
- 快速列表直接展示照片缩略图，能够发现明显的照片错配；
- 异常病害可以从列表直接进入完整维护；
- Word原文保留为不可改写的来源证据；
- 正式病害类型使用规范指标，不再依赖自由文本完全一致匹配；
- 照片实际关联只有一个可信来源；
- 修改、确认和忽略通过明确操作产生状态，不再允许任意选择校对状态；
- 兼容现有导入记录，不能推导的旧数据只进入待处理，不自动确认。

## 3. 非目标

- 本次不修改Word表格的解析规则；
- 不在快速列表中完成所有病害编辑；
- 不把病害描述或尺寸文字纳入系统扣分规则；
- 不取消最终的保存草稿、入库前检查和正式确认流程；
- 不自动确认存在任何无法解释冲突的数据。

## 4. 方案比较

### 4.1 增强版单卡片

保留当前单卡片结构，通过折叠和字段分组降低信息密度。

优点是改动较小；缺点是用户仍需在数百张卡片之间滚动，无法快速判断整体导入结果。

### 4.2 病害—照片左右分栏

每次只处理一条病害，左侧维护病害字段，右侧核对照片。

优点是单条精细维护清晰；缺点是进入页面后仍然从第一条开始逐条处理，正常项无法批量跳过。

### 4.3 快速校对列表 + 详情维护（采用）

上方用视觉列表展示全量病害和照片缩略图，完成筛选、预选和批量确认；选中一行后，下方打开左右分栏的详情维护区。

该方案同时满足快速判断和精细维护两个阶段，用户已选择采用。

## 5. 页面信息架构

页面从上到下由四部分组成：

1. 汇总与筛选工具栏；
2. 快速校对视觉列表；
3. 当前病害详情维护区；
4. 未关联照片区。

快速列表和详情区共享当前选中病害。切换列表行时，详情区更新，但未保存的草稿修改继续保留。

## 6. 快速校对区

### 6.1 汇总与筛选

顶部显示：

- 全部；
- 可批量确认；
- 需处理；
- 已确认。

问题筛选包括：

- 构件问题；
- 病害类型问题；
- 标度问题；
- 照片问题。

搜索范围包括：

- 构件编号；
- 病害位置；
- 病害类型；
- 照片编号。

默认先显示需处理项，其余病害保持Word顺序。筛选只改变显示范围，不清除用户已经取消或保留的选择。

### 6.2 视觉列表行

每行显示：

- 勾选框；
- 构件编号与位置；
- 规范病害类型；
- 标度；
- 最多三张关联照片缩略图及总数；
- 当前处理状态。

点击整行打开详情维护；点击缩略图打开详情并选中该照片。

为保证数百条病害下的性能，列表继续采用分页或虚拟化，不能一次挂载所有照片大图。缩略图使用独立的轻量资源。

### 6.3 自动预选

系统自动勾选满足全部条件的病害：

- 实际构件已关联到当前确认台账；
- 正式病害必填字段完整；
- 已选择当前构件类别适用的唯一规范病害指标；
- 标度有效且在该规范病害允许范围内；
- 不存在error或尚未解决的warning；
- 每个Word照片引用都有明确处理结论；
- 所有关联照片文件存在，照片关系为高置信候选或已经人工确认；
- 病害未被忽略。

异常项不自动勾选，也不能通过全选绕过校验。用户可以取消任何自动勾选项。

任何病害字段编辑、照片重新关联、照片处理结论变化或规范映射变化，都会重新计算资格；不再满足条件的病害立即取消预选。

### 6.4 批量确认

点击“确认所选正常项”前展示影响汇总，例如：

> 将确认128条病害、关联96张照片；233条异常项不会处理。

确认后：

- 选中病害的病害—照片组状态变为已确认；
- 满足资格的高置信照片关系变为已确认；
- 未修改病害的校对状态变为已确认；
- 已经人工修改的病害继续保留“已修改”审计状态，同时显示“本组已确认”；
- 已确认项继续保留在列表中，可通过筛选隐藏。

批量确认只修改当前草稿。保存草稿时由后端契约校验，最终入库前检查仍是权威阻断。

## 7. 详情维护区

详情区采用左右分栏。

### 7.1 左侧：正式病害档案

默认显示核心字段：

- 实际构件；
- 规范病害类型；
- 病害位置；
- 病害描述；
- 标度。

“检测量与补充信息”默认折叠，包含：

- 数量；
- 尺寸及结构化测量数据；
- 校对备注。

这些字段会进入病害档案，但数量和测量数据不直接参与当前系统评分。

“导入原文”默认折叠并且全部只读，包含：

- Word原文构件类别；
- Word原文构件编号；
- 原始病害类型；
- 原始位置和描述；
- 尺寸原文；
- Word原始照片编号。

修改过的正式字段显示“已修改”，并允许查看对应原值。

### 7.2 右侧：照片关系

右侧显示：

- 当前照片大图；
- 已关联照片缩略图；
- Word原文照片引用及逐项处理结论；
- 照片正确；
- 重新关联；
- 确认无关；
- 确认缺图；
- 原文引用有误。

正式照片关系只由照片操作维护，不再提供可编辑的“照片编号”文本框。

### 7.3 底部操作

- “确认并查看下一条”：确认当前病害与照片，随后打开下一条需处理病害；
- “仅保存修改”：保留当前组为待确认；
- “忽略病害”：二次确认后标记不入库。

只要存在未解决问题，“确认并查看下一条”保持禁用，并在按钮附近列出可理解的具体原因。

## 8. 字段调整

### 8.1 移除

- 移除手工“校对状态”下拉框；
- 移除正式档案区中可编辑的“照片编号”输入框。

底层仍保留校对状态，用于审计和入库；状态由实际编辑、确认和忽略动作产生。

### 8.2 新增

- 规范病害类型选择器；
- 字段原值与修改标记；
- Word照片引用的逐项处理结果；
- “原文引用有误”操作；
- “确认并查看下一条”；
- 快速列表的批量预选、批量确认和影响汇总；
- 可确认资格及不可确认原因。

### 8.3 降低优先级

- 数量；
- 尺寸与测量数据；
- 校对备注；
- 全部Word原文字段。

这些信息不删除，只移入折叠区域。

## 9. 状态模型

页面同时保留两个不同含义的状态，但不再让用户任意选择。

### 9.1 内容校对状态

- 待确认：尚未人工处理；
- 已确认：原导入内容未修改并已确认；
- 已修改：人工修改过正式档案字段；
- 已忽略：不进入正式档案。

编辑任意正式字段后自动变为已修改；忽略必须使用独立操作。

### 9.2 病害—照片组状态

- 待确认；
- 已确认。

编辑病害、修改照片关系或改变照片引用处理结论后，组状态自动回到待确认。完成单条或批量确认后变为已确认。

界面分别显示“人工修改”和“本组已确认”等只读徽章，避免将两个状态混成一个下拉框。

## 10. 规范病害类型

系统按检测年度锁定的技术评定规范和实际构件规范类别，加载适用病害指标。

正式病害应保存：

- `standard_defect_indicator_id`：稳定的规范病害指标ID；
- `defect_type`：该指标的当前显示名称；
- `source_defect_type`：Word原始病害类型，只读。

旧自由文本的处理：

- 唯一匹配时自动选择；
- 多个可能项时要求人工选择；
- 无法匹配或值为`/`时保持未选择并进入异常列表；
- 不允许仅凭模糊匹配自动确认。

系统评分使用规范指标ID和标度，不再将自由文本完全一致作为唯一关联方式。

## 11. 照片引用与实际关系

### 11.1 单一可信关系

照片的正式归属由照片候选的实际病害关联决定。Word照片编号只表示来源文档曾经怎样引用，不能直接决定最终归属。

### 11.2 原文引用处理结果

每个Word照片编号保存一个处理结论：

- `matched`：照片存在并正确关联本病害；
- `relinked`：原文引用有误，照片已关联其他病害；
- `missing`：Word引用但没有提取到照片，已人工确认缺图；
- `unrelated`：照片存在但与任何病害无关，已人工确认。

草稿合同增加：

```json
{
  "photo_reference_reviews": [
    {
      "photo_number": "2.1-1",
      "resolution": "relinked",
      "photo_candidate_id": "photo_0012",
      "resolved_defect_candidate_id": "defect_0031",
      "review_note": "原文编号引用错误"
    }
  ]
}
```

`photo_numbers`改为来源证据，不再由正式档案表单直接编辑。人工新增且没有Word来源的病害可以没有原文照片引用，但仍可关联实际照片。

## 12. 保存、校验与兼容

### 12.1 草稿保存

批量确认和详情编辑先作用于前端草稿，继续通过现有保存草稿入口持久化。编辑锁仍覆盖整个校对会话。

### 12.2 后端校验

后端保存草稿时校验合同；入库前检查再次验证：

- 规范病害指标适用于实际构件类别；
- 标度属于该病害允许范围；
- 照片引用处理结论与实际照片关系一致；
- 被确认病害不存在未解决问题。

### 12.3 旧记录兼容

旧记录没有规范病害指标ID或照片引用处理结果时：

- 根据实际构件类别和旧病害类型进行唯一匹配；
- 根据现有照片编号与实际关联推导`matched`；
- 根据已有缺图确认推导`missing`；
- 无法唯一推导的项目进入待处理；
- 兼容层不得自动生成“已确认”结论。

原始Word信息必须继续保留，兼容处理不能覆盖来源证据。

## 13. 异常处理

- 字段错误在对应控件附近显示，不只集中在页面顶部；
- 快速列表用问题类别和状态说明异常，不重复显示同义提示；
- 批量确认前重新计算选中项资格；
- 保存或入库校验失败时保留用户草稿，不丢失选择和详情展开状态；
- 若批量操作存在不能确认的项目，返回成功数量、失败数量和逐项原因，失败项继续留在需处理列表；
- 照片文件缺失、关联目标不存在或规范目录不可用时禁止确认。

## 14. 性能与交互状态

- 快速列表采用分页或虚拟化；
- 每行只加载最多三张轻量缩略图；
- 照片大图只在详情区按需加载；
- 筛选条件、选择集合、当前行和详情折叠状态在页面分区切换后保持；
- 以当前361条病害为最低性能验收规模。

## 15. 测试范围

### 15.1 快速列表

- 汇总、搜索、问题筛选和排序；
- 照片缩略图和照片数量；
- 自动预选与取消选择；
- 编辑后资格失效；
- 批量影响汇总；
- 批量确认正常项且不触碰异常项。

### 15.2 详情维护

- 规范病害类型按构件类别过滤；
- 字段修改、原值展示和状态流转；
- 折叠的检测量与导入原文；
- 照片正确、重新关联、无关、缺图和引用有误；
- 确认并跳到下一条；
- 忽略病害。

### 15.3 数据与兼容

- 新草稿合同校验；
- 规范指标与标度校验；
- 照片引用结论一致性；
- 旧记录唯一推导；
- 无法推导的数据保持待处理；
- 保存、重开页面后状态不丢失。

### 15.4 性能

- 361条病害首次可操作时间；
- 快速列表滚动和筛选响应；
- 缩略图懒加载；
- 批量确认响应时间；
- 分区切换后立即恢复列表和详情状态。

## 16. 验收标准

- 用户无需逐条打开正常病害即可完成批量确认；
- 快速列表中可以直接判断病害与照片是否明显错配；
- 任一异常项都能从列表定位到对应详情字段或照片；
- 正式病害类型能够稳定映射规范指标并参与系统评分；
- Word原文不可被人工改写；
- 正式照片关系和原文引用处理结论不会相互矛盾；
- 修改过的病害在确认后仍保留人工修改痕迹；
- 旧记录不会因兼容推导被错误自动确认；
- 当前361条病害规模下页面保持可用和流畅。
