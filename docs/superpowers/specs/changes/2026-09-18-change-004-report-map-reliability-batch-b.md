## 2. B1：下载资格和物理清理分离

到期以数据库 expires_at 为准，查询和下载接口立即视为不可下载，不依赖下一次定时清理。

新增报告任务产物台账，以 job_id 作为目录归属标识。台账不使用随任务历史级联删除的外键，因此年度/任务记录删除后仍保留清理目标。目录固定为受控 report_root/job_id，不接受客户端路径。旧任务迁移登记；历史 failed 任务缺少可靠写入存活信息，保守转 blocked，需核实后解锁。既有输出路径只用于核对，不能据此删除根外文件或另一个任务目录。

台账状态包含 active、pending、cleaning、blocked、cleaned，并保存重试次数、下次尝试时间、领取时间/标识、错误摘要、完成时间。正常到期及已确认结束的失败任务转 pending；事务领取少量任务，文件删除在事务外，完成回写必须匹配领取标识。领取中断后允许回收重试，重复清理和文件已不存在按幂等成功处理。

删除失败保留台账中的 expected_output_path 与错误记录，设置重试时间。任务行的下载路径和文件名在到期时清空，继续满足既有数据库约束；清理不再依赖这些下载字段。快照元数据在物理清理成功后清空，台账在保留期后回收。历史清除不删除尚未完成清理的关联任务。已无任务行的台账仍可完成清理，清理完成的台账在保留期后回收。

工具调用无响应、Office 恢复阻断或服务重启时无法证明写入停止的目录转 blocked，不自动删除。运维须先确认写入进程停止，再显式解除阻断；日志提供 job_id 与阻断原因，不自动按进程名终止 Office。未确认归属的孤儿目录只登记/报告，不无条件扫描删除。

清理组件负责路径验证和磁盘操作，仓储负责状态更新。所有路径验证必须在实际删除前执行；拒绝根目录、外部目录以及符号链接/目录联接跳转。

## 3. B2：任务受理时固定模板

边界为“新任务完成模板快照后入执行队列”。允许先保留 queued 任务行用于幂等防重，但未完成快照不得 enqueue；准备失败将该任务置 failed，并保留可重试的清理记录。重复受理返回已存在任务，不重新生成或覆盖其快照。

快照包含模板 ID、代码/名称、文件 ID、SHA-256、合同配置和模板校验结果。首次写文件前以独立数据库操作登记预期产物路径，快照事务失败仍保留目录归属；根目录配置改变时拒绝把另一个根下的缺失目录视为已清理。通过与模板更新一致的行锁，读取年度所选模板及其完整元数据，把有大小限制的源文件复制到 report_root/job_id/template.docx，核对文件摘要；模板修改和替换需等待这一短临界区结束。最终任务快照元数据持久化后才允许执行。

不在数据库事务内等待网络、报告装配或 Office。复制/落库失败保留清理目标，不把提交确认丢失等同于确定回滚。

Runner 读取任务快照，并再次核对任务副本摘要。模板相关预检及 ReportContext 的模板配置都从同一快照读取；业务事实仍沿用原有 REPEATABLE READ 上下文构建。后续模板替换、改名、改配置或停用不改变已固定的快照。旧排队任务没有可靠快照时按中断任务失败，不自动改用最新模板。

快照只属于一次临时任务，不建立永久模板/报告版本库。B1 负责与其他任务文件一起回收。

## 4. B3：图片格式与尺寸

保留原图字节，只在任务缓存生成派生图片。依据 Pillow 识别的实际格式判断兼容性，WebP 无论大小都转换；有透明信息的图片转 PNG，普通照片按既有 JPEG 质量策略处理。不放大小图。

先应用 EXIF 方向，再根据校正后宽高计算比例。兼容且无需转向/缩放的图片仍可直接使用。缓存使用独占名称避免同名或并行写入冲突；写失败或图片解码失败由装配层既有错误机制清晰报告，不把失败转换伪装成成功。

## 5. B4：ZIP 与 XML

先完成目录层检查：条目数、压缩/解压总量、单条目大小、压缩比、重复条目、路径、宏与嵌入对象。阻断后不读取 XML。实际读出字节仍有上限，不能只相信目录声明。

直接解析原始 XML 字节，遵循编码声明；禁止 DTD、实体、网络资源和恢复解析。根元素及 Relationship 必须属于允许的标准关系命名空间，属性合法，类型使用完整 URI 判断，不能只取末尾名字放行。

外部超链接按现有业务政策警告；外部图片/对象及附加模板等继续拒绝。不因引号、前缀、属性顺序或 UTF-16 编码不同改变判断。Content_Types 也按受限 XML 读取和校验，避免使用字符串搜索替代结构检查。

## 6. B5：自动地图条件写入

取图前记录 WGS-84 坐标、当前位置图 archived_file_id 和单调递增的 location_map_revision；网络请求在事务外。调用图件仓储时传入自动更新条件，在与人工上传/删除共用的桥梁行锁内复查坐标、文件标识和版本，并禁止覆盖人工来源。图件插入、更新和删除均递增版本，避免“原来没图→手工上传→又删除”的变化被忽略。

条件不满足返回明确的“输入已变化/保留已有图”结果，仅删除本次独占生成文件。事务提交不确定时继续沿用 P1 的新旧文件保留策略。手工上传接口语义不变，自动取图的失败/放弃不阻断报告生成。

## 7. B6：前端地图状态

使用明确的加载、可用、失败状态；有有效坐标时保留挂载容器，失败可显示静态图/说明和重试按钮。容器可隐藏，但重试初始化时必须可用。

每次 effect 只销毁自己创建的实例，并忽略已取消/过期的异步结果。坐标、桥梁或重试次数变化触发初始化。Loader 保持共享成功缓存，失败时移除失败脚本、清除计时器和事件，允许重试；旧尝试不得清空新尝试的缓存。

维持既有无坐标、无 key、无外网和静态图降级语义，不引入地图框架。

## 8. 接口、迁移和回退

新增迁移使用 IF NOT EXISTS/幂等约束，迁移在隔离 schema 中执行两次验证。不直接迁移业务数据库。任务 JSON 状态沿用现有枚举，快照和清理台账不向前端返回完整文件路径/配置。

仓储和清理组件保留必要兼容入口，已有测试和诊断工具默认行为不变。正式生成路径强制使用快照；诊断上下文工具可以继续读取当前模板。

回退应用前先停止新任务并处理 pending/blocked 清理记录。新表/列可保留，不能直接删除尚有清理目标的台账；不自动执行破坏性回滚迁移。运行指南记录升级迁移要求和 blocked 处理步骤。
