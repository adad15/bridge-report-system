# 变更提案 007：来源数据库台账核查、绑定对账与尺寸保真

日期：2026-09-21。用户已批准下一阶段前三步：查清构件信息、核对绑定规则、处理导入警告和尺寸边界。范围为既有流程调查和局部修复，正式入库、评分及报告另阶段执行。

## 输入和边界

复用来源只读快照 20260920-235718-b1a251 和三年度导入证据。原库只读，不写业务库，不自动确认完整台账，不根据待处理编号模糊匹配或选第一个候选。用户现有工作区改动保留。

## 核查任务

1. 枚举来源相关表及构件类别，记录 memberCount、具体节点数、实际被病害引用数、重复名称、范围编号、两侧编号与桥梁属性缺失情况。
2. 对照现有 C++ 类别加编号精确匹配、范围展开、两侧绑定、照片分配规则。已有真实完整台账不存在于本轮隔离环境时，输出绑定前置清单，不将源局部节点伪装成台账。
3. 枚举 2025/2026 对象警告及其原始事实；保留真正的业务冲突和人工确认项。
4. 对确定的尺寸保真缺陷增加失败回归，再做最小修复，复核真实三年度快照。

## 已发现的事实

支座 memberCount=3300，但具体节点为零。2025 桥面铺装 memberCount=33，具体节点54，含第N孔桥面与N#跨桥面铺装两种命名。来源分孔、结构体系、墩台、支座和构件编号规则属性为空，entityStructInfo 等补充结构表为空。源树不足以直接认定为完整台账。

现有尺寸逻辑对结构化列只调用 float；范围值被跳过后依赖描述解析。描述为空时丢失范围，描述冲突时可能以文本值覆盖来源范围而不提示冲突。

## 局部修复方案

在 source_db/defects.py 内增加结构化尺寸值解析，不改变合同或跨端接口：

- 单值沿用数值与原单位，拒绝非有限值及负尺寸。
- 显式识别以 ~、～、至 分隔的非负范围，保留上下限、单位和原始 source_text；倒置范围不擅自交换。
- 结构化范围与单值同等优先。描述只补缺失维度；来源与描述不一致时沿用已有冲突提示。
- 无法识别或无效的结构化表达产生 source_measurement_invalid 警告，包含原始值和单位；描述存在可解析补充值时允许补充，但保留警告。
- 保留现有单位别名比较；不在本轮新增跨量纲换算，不将单位不同的数值视为当然相同。
- 新警告接入前端逐条人工确认名单，仍禁止有警告时批量确认；解析器版本升至0.1.1。
- 现有照片归属和人工绑定政策保持，先检查证据和回归，不根据警告批量改业务事实。
