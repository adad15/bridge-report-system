# 变更提案 010：来源数据库 2026 年度报告输出验收

日期：2026-09-23。接续[变更提案 009](2026-09-23-change-009-source-database-assessment-audit.md)，以隔离库中已确认的百股大桥 2026 年度事实和正式系统评定，验证报告配置、生成、下载和 Word 版式。Word 文件导入不在本次范围。

## 目标和边界

从私有 PostgreSQL 的已确认年度生成 DOCX；生成前检查、模板快照、正式评定、430 条观测及 455 张照片须沿现有业务链。用独立脚本核对正式事实与装配上下文、病害表、照片编号和题注；用本机 Office/WPS 导出 PDF，检查实际页数、封面、目录、正文、图文页及横向附录。报告中的系统分数按模板既定一位小数显示，并注明年度页面两位小数的口径差异。

报告封面检测日期、报告编号、项目名称、检测单位由用户在年度“报告配置”页单独填写。它们与导入候选中的同名值彼此独立；保存其它配置的旧客户端请求不得清空已有封面值。四项可一起显式清空，日期必须是有效的 YYYY-MM-DD。生成任务固定当时的配置和模板副本。

模板最后的横向节不得重新从第 1 页计数。修复范围限于末节的页码起始属性，正文从第 1 页起算的设置保留；通过 PDF 核对纵向附录与横向附录之间连续编号。

## 实施和验证

1. 在隔离验收实例中，用现有报告页面保存模板、人员和设备，运行预检并生成第一份大样报告。保留原报告作为缺陷证据。
2. 对发现的封面空白及横向附录页码重置做最小修复：前后端年度配置读写和校验、前端输入框、模板末节页码。测试旧客户端保存兼容及空值处理。
3. 通过页面上传修正模板、人工填写四项仅供验收的封面值，重新生成并下载第二份 DOCX。独立比对正式数据库导出、生成上下文、DOCX 和 PDF；复核关键页面视觉。
4. 运行相关前端/C++ 测试、迁移及构建检查。证据写入 Git 忽略的本轮 `logs/acceptance`，不将隔离样本写入业务库。结束时停止私有服务，保留证据。

## 执行结果

最终任务成功生成 100 页 DOCX，内含 430 条正式观测对应表行和 455 张照片；来源病害去重数 381，报告显示 81.1 分、2 类。四项封面配置在生成上下文和文档中生效，PDF 中第 97～100 页的印刷页码为 92～95，横向节没有重置。独立核验差异为 0。结果和边界见[验收记录](../../../2026-09-23-source-report-acceptance-validation.md)。
