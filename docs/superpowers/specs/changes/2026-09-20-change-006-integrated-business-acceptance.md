## 数据与正确性基准

1. 构造符合当前合同 5.0 的小型可核对文档/业务数据，事先记录病害、照片、构件、评分预期。优先经公开业务 API 和界面创建，必需的账户初始化明确记录。
2. 复用仓库百股大桥与大凌河桥真实报告的只读副本，先确认输入格式和适用导入器。真实文档与合成样例结果分别记录。
3. 同桥两年度及另一座桥用于隔离验证。旧 v2 seed 不能直接作为当前业务验收数据；不得以测试放宽开关绕过正式校验。
4. 原报告评分与系统自主评分分别核对各自口径；不要求不同评分口径数值相等。

## 主流程与证据

通过生产前端执行登录、建桥/台账、年度创建、资料导入、校对病害/照片、构件绑定、预检查、确认、系统评分、报告配置、生成和下载。API 辅助用于准备数据与核对结果，不把直接写数据库或接口测试冒充界面主流程完成。

每步记录输入身份、操作、HTTP 状态、业务返回、持久化结果及耗时。断言数量、照片对应、绑定目标、年度和桥梁身份一致。状态为通过、失败、阻塞或未覆盖，不以页面能打开代表业务正确。

## 异常与隔离

- 在未完成请求下切换桥梁、年度和导入记录，确认迟到响应不污染当前页面。
- 修改、保存、离开、再进入，检查草稿版本及未保存标记。
- 双会话竞争同一导入记录，检查锁、只读和恢复。
- 重复点击生成及刷新，确认无重复活动任务。
- 模块加载失败、工具服务暂不可用的恢复，只在隔离环境注入。
- 发现确定缺陷时做最小必要修复并增加针对性回归；涉及业务规则或接口语义改变则单独说明，避免混入大重构。
