# 2026-07-24 设计：构件绑定中的用户选择式范围拆分

## 1. 背景

部分检测报告把多个实际构件合写在同一病害行中，例如：

- `1-1#板~1-25#板`
- `2-1#板～2-25#板`
- `3-2#铰缝~3-5#铰缝`

当前导入会忠实保留 Word 原文，因此构件绑定界面只能看到一个范围编号，无法把病害绑定到范围内的各个实际构件。

本功能不改变 Word 解析结果。只有用户在构件绑定界面明确选择范围行并确认预览后，系统才拆分相应病害。未选择的范围永久保持原样。

## 2. 目标

1. 在构件绑定界面识别可安全拆分的构件范围行。
2. 用户可多选范围行，预览后一次性拆分。
3. 一条绑定行引用的所有病害一起拆分。
4. 拆分病害继承原文字、测量信息和标度。
5. 原病害关联的照片候选随每条拆分病害复制，但复用同一归档文件。
6. 拆分后按已确认台账自动绑定唯一匹配的实际构件。
7. 为拆分病害保留永久来源信息，并在人工确认前进入“需要处理”。
8. 拆分在后端事务内原子执行，预览与应用之间的数据变化必须被识别。

## 3. 非目标

1. 不在 Word 解析阶段自动拆分范围。
2. 不修改报告原文。
3. 不读取或保存 Word 的“病害扣分”列。
4. 不人为分摊、缩放或重算拆分病害的标度。
5. 不推翻已经绑定或已标记缺失的人工处理结果。
6. 不为复制的照片重复创建磁盘文件。
7. 不扩展为任意表达式、离散列表或跨类型构件解析器。

## 4. 用户流程

### 4.1 选择

构件绑定概览由后端识别拆分资格。只有同时满足以下条件的行显示复选框：

- 状态为 `unmatched` 或 `ambiguous`；
- 构件编号符合第 6 节的安全范围规则；
- 展开数量不超过单范围上限。

用户可以勾选多个范围行。页头提供“拆分构件（已选 n 行）”按钮。筛选切换、概览刷新或绑定操作导致某行不再可拆时，该行自动从选择中移除。

### 4.2 预览

点击“拆分构件”后，前端把选中的 `(part_name, component_number)` 交给后端预览接口。后端读取当前导入候选 JSON 和已确认台账，返回：

- 每个原范围编号；
- 展开后的起止编号和构件数量；
- 原病害数与新病害数；
- 原照片候选数与新照片候选数；
- 将自动绑定、拆分后未匹配、拆分后歧义的数量；
- 整批汇总；
- 影响令牌。

预览对话框必须展示以下评分提示：

> 拆分后多个实际构件将分别参与评分，可能降低部件及全桥评分。

预览不修改数据库。

### 4.3 应用

用户确认后，前端把原选择和影响令牌交给应用接口。后端锁定导入记录并重新校验：

- 导入仍处于 `待校对`；
- 当前台账仍是预览时的已确认修订版；
- 选中行仍存在并保持 `unmatched` 或 `ambiguous`；
- 范围展开结果、原病害和照片集合未变化；
- 影响令牌仍与当前数据一致；
- 整批生成数量未超过安全上限。

全部校验通过后，在同一事务中完成病害拆分、照片候选复制、唯一构件自动绑定、警告与追溯信息写入。任一项失败则整批回滚。

应用成功后返回新的构件绑定概览。前端关闭对话框、清空选择并同步页头和侧栏统计。

## 5. 接口设计

在现有路径下新增：

- `POST /api/import-records/{import_id}/component-binding/split-preview`
- `POST /api/import-records/{import_id}/component-binding/split-apply`


### 5.5 错误

使用稳定错误码和具体消息：

- `component_range_not_splittable`：范围无法安全解析；
- `component_range_split_limit_exceeded`：超过单范围或整批上限；
- `component_range_split_conflict`：行已绑定、已标记缺失或状态变化；
- `component_range_split_stale`：影响令牌与当前候选 JSON 或台账修订版不一致；
- `component_range_split_target_missing`：预览中的原范围行已不存在；
- `component_range_split_failed`：数据库或事务提交失败。

冲突响应应包含挡住整批操作的 `part_name` 和 `component_number`。前端显示后端消息，不把这些错误折叠成“操作失败”。

## 6. 安全范围语法

### 6.1 支持

支持半角和全角波浪号：

- `~`
- `～`

两端必须能拆成相同的固定前缀、一个末位整数和相同的固定后缀。只展开这个末位整数。

示例：

| 原文 | 结果 |
|---|---|
| `1-1#板~1-25#板` | `1-1#板` 至 `1-25#板` |
| `2-1#板～2-25#板` | `2-1#板` 至 `2-25#板` |
| `3-2#铰缝~3-5#铰缝` | `3-2#铰缝` 至 `3-5#铰缝` |

分隔符两侧允许空白。解析比较使用现有构件编号归一化规则，生成编号使用起点的格式模板，避免无关的文字改写。

### 6.2 拒绝

以下情况不提供复选框，直接保持原样：

- 前缀不同；
- 构件类型后缀不同；
- 起点大于终点；
- 任一端缺少末位整数；
- 出现多个范围分隔符；
- 可产生多种解释；
- 展开后只有一个编号；
- 展开数量超过 500。

一次操作最终生成的病害候选不得超过 2000 条。上限按所有选中范围的结果病害数之和计算。

## 7. 病害拆分规则

对于绑定行引用的每条原病害，按范围内每个编号生成一条新病害，并移除原范围病害。

每条新病害：

1. 生成在本次导入候选 JSON 内唯一的新 `candidate_id`。
2. 把 `component_number` 改为当前展开编号。
3. 原样复制：
   - `source_structure_part`
   - `component_name`
   - `defect_type`
   - `defect_location`
   - `defect_description`
   - `quantity_text`
   - `measurement_text`
   - `measurements`
   - `photo_numbers`
   - `defect_scale`
   - `severity`
   - `remark`
   - `source_ref`
   - `confidence`
   - `review_note`
4. 清空原构件绑定结果和匹配候选，随后执行第 9 节的重新匹配。
5. 把 `review_status` 和 `group_review_status` 重置为 `待确认`。
6. 保留原对象级警告；警告中指向旧候选 ID 的 `target_candidate_id` 替换为新 ID。
7. 增加临时警告 `component_range_split_review_required`。
8. 增加永久 `range_split_origin` 元数据。

导入级 `warnings` 或 `errors` 如果通过 `target_candidate_id` 指向被拆病害，应为每条新病害复制一份并改写目标 ID；不得留下指向已移除候选的悬空引用。

## 8. 永久来源与临时检查

### 8.1 候选合同

`DefectCandidate` 新增可选字段：

```json
{
  "range_split_origin": {
    "operation_id": "uuid",
    "source_candidate_id": "defect_0001",
    "source_component_number": "1-1#板~1-25#板",
    "expanded_component_number": "1-7#板",
    "split_index": 7,
    "split_count": 25,
    "operated_by_user_id": "uuid",
    "operated_at": "2026-07-24T16:00:00+08:00"
  }
}
```

该字段在 Python Pydantic 合同、JSON Schema、C++ 合同校验和前端 TypeScript 合同中保持一致。字段可选，因此历史数据无需迁移。

### 8.2 临时警告

每条新病害增加：

```json
{
  "code": "component_range_split_review_required",
  "message": "该病害由构件范围“1-1#板~1-25#板”自动拆分，请人工核对。",
  "severity": "warning",
  "target_candidate_id": "new-candidate-id"
}
```

该警告自动进入现有“需要处理”列表和对象警告统计。病害卡片显示醒目的“范围拆分 · 待核对”标识。

用户完成病害与照片联合确认时，删除这条临时警告；永久 `range_split_origin` 不删除。确认后的病害卡片显示只读“由范围拆分”来源徽标。

### 8.3 正式事实

正式入库时把 `range_split_origin` 写入 `defect_observations.source_raw_cells_json`，与原始 Word 行信息一并保存，不新增数据库列。病害档案接口读取该字段并展示：

> 由 `1-1#板~1-25#板` 拆分

该来源信息不参与评分，不允许通过普通病害编辑覆盖。

## 9. 自动绑定

每条新病害使用当前已确认台账和现有部件名称到规范类别的对照执行匹配：

1. 在相同规范类别下，归一化编号有且只有一个活动构件时：
   - 写入 `bridge_component_id`；
   - 写入规范类别、结构部位和台账修订版；
   - `component_match_method` 使用现有能表达唯一归一化匹配的方法。
2. 没有对应编号时保持未匹配。
3. 有多个合法同号构件时写入候选 ID，状态为歧义。

拆分不允许自动跨类别绑定。

## 10. 照片候选复制

对每条原病害，找到所有 `linked_defect_candidate_id` 指向它的照片候选。对于每条新病害：

1. 为每个原照片候选生成一个新照片候选和新 `candidate_id`。
2. `linked_defect_candidate_id` 指向当前新病害。
3. 原样复制：
   - `photo_number`
   - `extracted_file`
   - `match_status`
   - `source_ref`
   - `confidence`
   - `review_status`
   - `warnings`
4. 照片警告中指向原照片候选或病害候选的目标 ID，应改写为对应的新 ID。
5. 多个照片候选可以引用同一个 `archive_relative_path`；不得复制归档文件。

完成所有复制后删除指向原范围病害的原照片候选，确保不存在悬空关联。

如果病害的 `photo_numbers` 有值但不存在对应照片候选，拆分病害继续保留这些编号，现有缺图检查会分别生成待处理项。

## 11. 评分语义

Word 的扣分和评分列不进入候选合同。本功能只复制 `defect_scale`。

拆分后的每个实际构件独立参与系统评定，因此原范围覆盖多个实际构件时，受影响构件数量会增加，部件和全桥评分可能下降。不得把原扣分平均分摊到新病害，也不得为保持拆分前总分而修改标度。

现有评分规则保持不变：

- 同一实际构件、同一病害指标的多条记录按最高标度聚合；
- 不同实际构件分别评定；
- 构件、部件和全桥结果继续使用现有规范算法，不做简单线性求和。

## 12. 并发与原子性

### 12.1 影响令牌

影响令牌至少覆盖：

- 导入记录 ID；
- 当前 `parsed_result_json` 的稳定摘要；
- 已确认台账修订版 ID；
- 规范化并排序后的选择集合；
- 预览展开结果摘要。

令牌对客户端不透明。应用接口不能信任客户端提交的展开编号、计数或绑定结果，必须由后端重新计算。

### 12.2 事务

应用接口使用行锁读取导入记录。所有病害、照片和导入级警告变更合并为一次 `parsed_result_json` 更新。提交失败、影响令牌失效或任一目标不合法时不写入任何部分结果。

## 13. 审计

每次成功操作生成一个 `operation_id`。拆分来源元数据记录操作人和时间。后端日志记录：

- 导入记录 ID；
- 操作 ID；
- 操作人；
- 选中范围；
- 原病害数；
- 新病害数；
- 新照片候选数；
- 自动绑定、未匹配和歧义数量。

日志不得记录认证令牌或归档文件内容。

## 14. 测试

### 14.1 范围解析单元测试

- 半角和全角波浪号；
- 分隔符两侧空格；
- 同前缀、同后缀的连续编号；
- 前缀不同；
- 构件类型不同；
- 倒序；
- 多个分隔符；
- 无法唯一解释；
- 单编号结果；
- 单范围超过 500。

### 14.2 仓储与接口测试

- 单行和多行预览计数；
- 一行引用多条病害；
- 多张照片候选复制；
- 自动绑定、未匹配和歧义混合；
- 影响令牌稳定且对数据变化敏感；
- 应用成功后原范围病害和原照片候选被移除；
- 任一目标失效时零写入；
- 已绑定和已标记缺失行拒绝；
- 非待校对导入拒绝；
- 台账修订版变化拒绝；
- 一次生成超过 2000 条病害拒绝；
- 错误响应包含具体范围。

### 14.3 合同与校对测试

- `range_split_origin` 四端合同一致；
- 历史候选不含该字段仍合法；
- 临时警告进入“需要处理”和对象警告统计；
- 联合确认只移除临时警告，不删除永久来源；
- 导入级目标警告不存在悬空 ID；
- 候选 ID 和照片候选 ID 在本次导入候选 JSON 内唯一。

### 14.4 评分测试

- 每条新病害继承原标度；
- 不同实际构件分别参与评定；
- 同一实际构件、同一指标仍只取最高标度；
- 不引入 Word 扣分字段；
- 构件、部件和全桥结果与现有算法一致。

### 14.5 正式入库与档案测试

- `range_split_origin` 写入 `source_raw_cells_json`；
- 档案接口和页面可追溯原范围；
- 多个正式照片记录可引用同一归档文件；
- 拆分来源不参与评分输入。

### 14.6 前端测试

- 只有符合资格的未匹配/歧义行显示复选框；
- 多选、取消选择和状态变化后的选择清理；
- 预览逐行及汇总计数；
- 评分影响提示；
- 过期预览和具体失败范围；
- 应用成功后关闭对话框并刷新统计；
- 病害卡片的临时和永久标识；
- 未选择范围不发生变化。

### 14.7 回归

真实 Word 解析回归在用户执行拆分前必须与当前版本完全一致，包括病害数、照片候选数、候选内容和评分输入。

## 15. 验收标准

1. 用户不选择范围时，系统行为与当前版本一致。
2. `1-1#板~1-25#板` 可预览为 25 个实际构件。
3. “引用 3 条”的范围行应用后生成 75 条病害。
4. 每条新病害文字描述、测量信息和标度与原病害一致。
5. 每条新病害获得独立照片候选，照片文件不重复归档。
6. 唯一台账匹配自动绑定；缺失和歧义保留待处理。
7. 所有新病害带临时人工检查警告和永久拆分来源。
8. 联合确认后临时警告消失，永久来源仍可在校对和档案中查看。
9. 拆分后的多个实际构件按现有规范分别参与评分。
10. 数据变化或任一目标失败时整批零写入。
11. 已绑定、已标记缺失、非法范围和超限范围不能拆分。
12. 后端错误能指出具体失败范围。
