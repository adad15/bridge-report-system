# 模块 06 验收问题修复设计

> 日期：2026-07-15
>
> 状态：设计已确认，待实施
>
> 影响模块：03、04、05、06 及账号/重开共用能力

## 1. 背景

模块 06 的档案查询、病害线索、评分展示、历史修订和真实 Word 回归已完成，但验收发现四项正式数据边界问题：

1. 人工选择“接受 Word 值”或“采用复算值”后，C++ 未约束最终分必须等于所选来源。
2. `warnings_only` 重开只比较病害数组，仍可能越权修改评分、照片等数据。
3. 多用户同时保存同一导入记录时，整份草稿可能相互覆盖。
4. 合同允许病害扣分为 0，但三端评分算法将 0 判为非法。

本设计修复上述四点。多用户并发不采用普通乐观版本冲突方案，改用导入记录级独占租约锁。

## 2. 目标与非目标

### 2.1 目标

- 一条可编辑导入记录在任一时刻只允许一个浏览器页面持有编辑权。
- 其他用户仍可只读查看，并能看到当前编辑者。
- 异常关闭后锁可自动过期，不形成永久死锁。
- 所有正式写入路径在后端验证编辑锁，客户端不能绕过。
- 人工评分选择与正式最终分严格对应。
- `warnings_only` 只允许修正数据库原草稿中带警告的病害，并由后端控制评分联动。
- 0 扣分在 Python、C++、TypeScript 中具有一致、可计算的语义。

### 2.2 非目标

- 不实现多人协同编辑或字段级合并。
- 不实现草稿自动保存。
- 不使用 `localStorage`、IndexedDB 等恢复未保存内容。
- 不保留浏览器异常关闭前尚未手动保存的编辑内容。
- 不改变模块 06“只读档案优先、有限线索写入”的总体定位。

## 3. 独占编辑租约锁

### 3.1 锁语义

进入可编辑校对页时，页面必须先取得导入记录的独占租约锁。锁绑定到当前用户、登录会话和当前浏览器页面返回的随机锁令牌。

- 页面每 30 秒续租一次。
- 每次成功续租把到期时间延长至当前时间后 2 分钟。
- 正常退出、确认入库、取消导入或放弃重开时立即释放。
- 浏览器崩溃、断网或电脑关闭时不保证发送释放请求；连续 2 分钟无心跳后锁自动失效。
- 同一用户的另一个页面不共享明文锁令牌，因此只能只读查看。
- 明文锁令牌只保存在当前页面内存，不持久化到浏览器存储。
- 刷新或异常关闭导致锁令牌丢失时，若尽力释放请求未到达，用户需等待原锁过期。

未手动保存的编辑只存在于浏览器内存。异常关闭后直接丢失，数据库保留最后一次成功保存的草稿。

### 3.2 数据库

新增幂等迁移 `database/migrations/005_import_record_edit_locks.sql`，不回改已经执行过的 004。

新增 `import_record_edit_locks`：

| 字段 | 说明 |
|---|---|
| `import_record_id` | 主键并外键到 `import_records`，保证每条记录最多一个锁 |
| `user_id` | 当前编辑者 |
| `user_session_id` | 取得锁的登录会话 |
| `lock_token_hash` | 随机明文令牌的安全哈希，唯一 |
| `acquired_at` | 首次取得时间 |
| `last_heartbeat_at` | 最近一次成功续租时间 |
| `expires_at` | 租约到期时间 |

用户展示信息从 `users` 关联读取，不把显示名冗余进锁表。取得锁时在数据库事务内清理或覆盖过期锁，不要求后台定时任务。

新增 `import_record_edit_lock_events` 审计表，至少保存 `import_record_id`、动作、原持有人、操作人、发生时间和原因。第一版记录 `force_released`，后续可复用相同结构记录其他锁事件。管理员强制释放必须写入该表，不得只保存在前端或进程日志。

### 3.3 原子性

取得锁采用数据库唯一约束和事务保证并发安全。两个请求同时竞争同一记录时只能一个成功。

已确认记录的重开必须在同一事务内完成：

```text
验证重开范围和角色
→ 验证不存在有效锁
→ 创建租约锁
→ 快照原草稿并把记录翻回待校对
→ 返回锁令牌
```

任一步失败都整体回滚，不允许出现已经重开但无人持锁的中间状态。

确认入库、取消导入和放弃重开成功时，业务状态变更与锁释放同属一个事务。

## 4. 编辑锁 API

### 4.1 取得锁

```http
POST /api/import-records/{id}/edit-lock
```

成功返回明文 `lock_token`、`expires_at` 和 30 秒心跳间隔。存在未过期锁时返回 `409 import_record_locked`，并返回编辑者显示名、取得时间和到期时间，但不返回锁令牌。

### 4.2 心跳

```http
POST /api/import-records/{id}/edit-lock/heartbeat
X-Edit-Lock-Token: <token>
```

后端验证记录、用户、会话、令牌和未过期状态。成功后续租 2 分钟。锁错误、过期或被收回时返回 409，前端立即停止写入并切换只读。

### 4.3 释放与强制释放

```http
DELETE /api/import-records/{id}/edit-lock
X-Edit-Lock-Token: <token>

POST /api/import-records/{id}/edit-lock/force-release
```

正常释放只允许持锁页面。强制释放仅管理员可用，请求必须携带非空原因，前端需要二次确认。

应用内正常返回时等待释放完成再导航。刷新、关闭标签页时使用带 `keepalive` 的尽力释放请求；发送失败由租约过期兜底。

### 4.4 必须验证锁的业务接口

以下操作除原有身份、角色和状态检查外，还必须验证 `X-Edit-Lock-Token`：

- 保存草稿；
- 入库前检查；
- 确认入库；
- 取消导入；
- 放弃重开修改；
- 重开后的所有校对写入。

纯读取接口不要求编辑锁。GET review 响应增加当前锁的只读摘要，供页面和导入记录列表显示“某某人正在编辑”。

## 5. 前端页面状态

校对页明确区分：

1. 当前页面持锁：正常编辑，显示“你正在编辑”。
2. 其他用户持锁：只读，显示“张工正在编辑”和开始时间。
3. 当前用户其他页面持锁：只读，显示“你已在另一个页面编辑”。
4. 锁过期、心跳确认丢失或被管理员收回：停止全部写入，提示刷新或重新取得锁。

心跳暂时失败但尚未确认锁已丢失时，页面显示“连接异常，正在确认编辑权”，并暂停保存、预检和确认按钮。

正常离开且草稿有未保存修改时，提示“未保存内容将丢失”。用户确认后释放锁并离开。系统不自动保存、不建立本地恢复缓存。

## 6. 构件评分最终值约束

C++ 入库前检查是最终可信边界，必须独立复算并验证以下关系。

### 6.1 一致

- `source_score` 和后端复算值均存在；
- 两者按统一两位小数规则相等；
- `confirmed_score == round2(source_score)`；
- 处理原因为空。

### 6.2 人工采用复算值

- 扣分引用完整且可复算；
- `calculated_score` 与后端未提前舍入的独立复算值一致；
- `confirmed_score == round2(后端独立复算值)`；
- 处理原因非空。

### 6.3 人工接受 Word 值

- `source_score` 存在；
- `confirmed_score == round2(source_score)`；
- 处理原因非空；
- 既适用于来源分与复算分不一致，也适用于确实无法复算的情形。

不满足时返回阻断错误 `component_score_confirmed_value_mismatch`，错误信息包含构件、选择状态、期望值和当前值。`ConfirmPlan` 只消费已经通过该校验的数据。

## 7. `warnings_only` 范围

### 7.1 允许修改

仅允许修改数据库当前草稿中 `warnings` 非空的病害候选业务字段，包括构件类别、构件编号、病害位置、病害类型、病害特征、标度、扣分、数量、尺寸原文和该候选的校对状态。

是否属于警告病害只以保存前的数据库草稿为准，客户端修改或伪造 `warnings` 不能扩大范围。

### 7.2 禁止修改

- 新增或删除病害；
- 修改无警告病害；
- 修改照片候选或照片关联决定；
- 修改全桥、结构分部和部件评分；
- 人工修改构件评分的来源分、最终选择或最终分；
- 修改桥梁、检测年度、来源证据、导入级警告/错误和其他顶层数据。

前端在 `warnings_only` 下将评分区设为只读并隐藏所有评分决策操作。

### 7.3 扣分变化引起的评分联动

警告病害扣分改变时，C++ 后端从修改后的病害证据重新生成受影响构件评分的扣分引用、复算分、计算明细和自动校验状态。客户端预览仅用于显示，不是可信输入。

如果复算变化导致需要重新作出人工评分选择，`warnings_only` 不允许顺带完成该选择，保存或后续预检应返回明确提示，要求管理员通过完整重开流程处理评分差异。其他构件评分及所有非构件评分必须保持不变。

保存顺序为：

```text
验证编辑锁
→ 读取数据库当前草稿
→ 校验警告病害允许范围
→ 拒绝其他字段变化
→ 后端重建受影响构件评分
→ 验证合同
→ 保存草稿
```

## 8. 0 扣分语义

统一定义 `0 <= defect_deduction <= 100`。空扣分集合仍表示无法复算，但集合中的 0 是合法扣分并参与降序证据序列，不增加累计扣分。

固定跨语言样例：

| 输入 | 两位小数结果 |
|---|---:|
| `[0]` | `100` |
| `[0, 0]` | `100` |
| `[35, 0]` | `65` |
| `[35, 20, 0]` | `55.81` |
| `[100, 0]` | `0` |

Python、C++ 和 TypeScript 评分函数、扣分完整性判断、导入器、C++ 预检和共享测试必须一致。合同和 JSON Schema 已允许 0，只需移除算法及说明中 `(0,100]` 和“0 非法”的旧语义。

## 9. 错误处理

至少提供以下稳定错误码：

| 错误码 | HTTP | 含义 |
|---|---:|---|
| `import_record_locked` | 409 | 记录被其他页面持锁 |
| `edit_lock_required` | 409 | 写操作没有锁令牌 |
| `edit_lock_invalid` | 409 | 用户、会话或令牌不匹配 |
| `edit_lock_expired` | 409 | 租约已过期 |
| `edit_lock_force_released` | 409 | 锁已被管理员收回 |
| `component_score_confirmed_value_mismatch` | 400 | 最终分与人工选择不对应 |
| `reopen_scope_violation` | 400 | `warnings_only` 修改越界 |

错误响应不得暴露锁令牌哈希、会话令牌或服务器内部路径。

## 10. 测试与验收

### 10.1 编辑锁

- 两个用户或同一用户两个页面并发取得锁，只有一个成功；
- 未持锁页面可读取但不能保存、预检、确认或取消；
- 缺失、错误、过期令牌均被拒绝；
- 心跳只允许所有者续租并正确延长到期时间；
- 连续 2 分钟无心跳后另一用户可以取得锁；
- 正常退出、确认、取消和放弃重开立即释放锁；
- 管理员可带原因强制释放，普通用户不可；
- 强制释放后原页面不能继续写入；
- 重开与取得锁具有事务原子性。

### 10.2 评分最终值

- 采用复算值但最终分不等于两位小数复算值时拒绝；
- 接受 Word 值但最终分不等于来源值时拒绝；
- 一致状态但最终分不等于来源/复算值时拒绝；
- 三种合法状态仍可正常确认入库。

### 10.3 `warnings_only`

- 修改警告病害位置成功；
- 修改警告病害扣分并由后端复算成功；
- 修改无警告病害、新增/删除病害、照片、非构件评分或其他顶层数据均拒绝；
- 客户端伪造警告数组不能扩大范围；
- 任意指定构件最终分被拒绝；
- 评分变化需要人工决策时明确要求完整重开。

### 10.4 0 扣分与全量回归

- Python、C++、TypeScript 共享 §8 的全部样例；
- 真实 Word 的 25 条病害、31 个照片候选、36 个 Word 图片、31 张归档照片、15 个原评分项保持不变；
- `1-1#板=65`、`1-2#板=65`、`2-1#板=55.81`、上部承重构件 `86.62`、全桥 `85.61` 保持不变；
- Python、前端、C++/PostgreSQL 全量测试和前端生产构建通过；
- 004、005 迁移可幂等复跑；
- 双账号手工验证锁定、只读提示、正常释放、异常超时和管理员接管。

只有在四项问题均有后端防绕过测试、全量自动化和真实 Word 回归通过后，模块 06 才可重新验收。当前工作区中的共用后端路由、前端校对文件、账号和重开能力均属于本次模块 06 验收范围。
