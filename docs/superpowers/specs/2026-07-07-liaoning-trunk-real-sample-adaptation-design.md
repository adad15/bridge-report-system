# 辽宁国省干线真实样例适配设计

日期：2026-07-07

## 1. 背景

`2026-07-07-liaoning-trunk-word-rules-design.md` 的规则模块化已实施完成，动态夹具测试全部通过。但对用户提供的真实非正式报告（绕阳河二号桥样例）执行 `/imports/word/parse` 时返回 `rating_table_not_found`。

读取层诊断（Task 3 的 `docx_diagnostics` 与 customXml 下钻）确认五张目标表都能读取，失败原因在规则层与真实样例的三处结构差异：

1. 病害表列名与夹具不同。真实表头为：

   ```text
   序号 | 部件名称 | 构件编号 | 病害位置 | 病害类型 | 病害特征 | 标度 | 病害扣分 | 构件评分 | 照片编号
   ```

   当前列查找按 `构件/位置/病害/数量/尺寸` 关键词匹配，且“病害”子串会先命中“病害位置”列。

2. `表4.1-2 总体技术状况评定表` 是矩阵布局，不是“层级”行布局。真实表每行是一个评价部件的分数行，全桥总分、综合评级、结构评分、权重、等级在合并单元格中逐行重复：

   ```text
   结构 | 类别 | 评价部件 | 构件数量 | 构件评分 | 桥梁部件技术状况评分 | 桥梁结构技术状况评分 | 桥梁结构组成权重 | 等级 | 桥梁总体技术状况评分 | 综合评级
   上部结构 | 1 | 上部承重构件 | 1个 | 55.81 | 86.62 | 87.45 | 0.4 | 2 | 85.61 | 2类
   ```

   当前解析器按“层级”列区分全桥/结构分部/评价部件行，对矩阵布局完全失效。

3. 病害照片题注在独立的 1 行小表格单元格里，不在段落中。当前 `find_photo_captions` 只扫段落。另外该样例未按 F9 刷新域，题注中的“照片2.1-1”编号是未刷新域，文本中不存在；病害表“照片编号”列的值是完整的。

其他诊断结论：

1. 表号中的连字符是 `w:noBreakHyphen` 元素，python-docx 文本读取正确，原始 XML 字符串搜索会漏。
2. 病害表存在跨页续表（表题相同、表头为空），现有表头校验已能拒绝，无需处理。
3. `表4.1-1 桥梁部件权重计算表` 表题识别正常。

## 2. 目标

1. `辽宁国省干线` 规则能解析真实非正式报告的三张病害表，产出病害候选。
2. 能解析矩阵布局的 `表4.1-2`，产出 `overall`、`structure_parts`、`evaluation_parts`。
3. 病害照片题注扫描扩展到表格单元格。
4. 保持动态夹具（“层级”布局、旧列名）继续通过，两套布局/表头都受测试覆盖。
5. 真实样例端到端调用 `/imports/word/parse` 返回 200 与合法契约 JSON。

本设计不负责：

1. 自动模板识别。
2. `附录1 桥梁技术状况评定表` 或正文评分兜底。
3. `.doc`、PDF、OCR。
4. 照片编号域自动刷新。导入前用户手动全选并按 F9 刷新仍是流程前提。
5. 病害扣分、构件评分列入契约。评分以 `表4.1-2` 为准。

## 3. 用户已确认决策

| 决策 | 结论 |
| --- | --- |
| 完好行处理 | 跳过，不生成病害候选；顶层写 info 说明跳过的行 |
| 构件字段映射 | `component_name` = 构件编号（1-1#板），`component_alias` = 部件名称（上部承重构件） |
| 标度列 | 写入契约 `severity` 字段（原文，如 `"2"`） |

## 4. 病害表列别名

### 4.1 别名定义

`WordRuleSet` 新增病害表列别名，列查找改为按别名优先级匹配：对每个字段依次尝试各别名，先规范化全等，再子串包含；命中即停。

| 契约字段 | 别名优先级 | 真实表命中 | 旧夹具命中 |
| --- | --- | --- | --- |
| component_name | 构件编号、构件 | 构件编号 | 构件 |
| component_alias | 部件名称 | 部件名称 | 无（None） |
| defect_location | 病害位置、位置、部位 | 病害位置 | 位置 |
| defect_type | 病害类型、病害 | 病害类型 | 病害 |
| measurement_text | 病害特征、尺寸 | 病害特征 | 尺寸 |
| quantity_text | 数量 | 无（None） | 数量 |
| severity | 标度 | 标度 | 无（None） |
| photo_numbers | 照片编号、照片 | 照片编号 | 照片编号 |

表头文本匹配前做规范化（去空白，兼容“部件 名称”这类带空格表头）。

### 4.2 单元格值清洗

单元格值为 `/` 视为空。空的 `defect_type`、`defect_location` 沿用现有回退（`未识别病害`、`未识别位置`）。

### 4.3 完好行跳过

同时满足以下条件的行不生成病害候选：

1. 病害类型列为空（含 `/`）。
2. 病害特征（measurement_text 来源列）包含 `基本完好`。

每张表解析完后，如有跳过行，顶层 `warnings[]` 写一条：

```json
{
  "code": "liaoning_trunk_intact_row_skipped",
  "message": "表2.3-1 中 3 行构件基本完好，未生成病害候选：栏杆、护栏（左侧护栏）…",
  "severity": "info",
  "target_candidate_id": null
}
```

### 4.4 真实样例预期

- 表2.1-1：12 条病害候选，0 行跳过。
- 表2.2-1：6 条病害候选，1 行跳过（河床）。
- 表2.3-1：3 条病害候选，3 行跳过（左右护栏、管养牌）。
- 共 21 条，`photo_numbers` 从“照片2.1-1 照片2.1-2”样式解析出编号本体。

## 5. 表4.1-2 矩阵布局

### 5.1 布局识别

`表4.1-2` 支持两种布局，均在规则集中定义表头要求：

1. `层级` 布局（现状，动态夹具使用）：表头含 层级/结构部位/类别编号/评价部件/评分/权重/等级/构件评分。
2. `矩阵` 布局（真实样例）：表头含 结构/类别/评价部件/构件数量/构件评分/桥梁部件技术状况评分/桥梁结构技术状况评分/桥梁结构组成权重/等级/桥梁总体技术状况评分/综合评级。

表题命中 `表4.1-2` 后，先按矩阵表头识别，再按层级表头识别，两者都不满足则继续找下一张表。

### 5.2 矩阵解析

1. 逐数据行读取，`结构` 列不属于 上部结构/下部结构/桥面系 的行跳过。
2. `evaluation_parts[]`：按（结构、类别、评价部件）聚合。`part_score` 取 桥梁部件技术状况评分；每行的（构件数量、构件评分）追加为 `score_rows[]`，“1个”解析为 1。
3. `structure_parts[]`：按 结构 列首次出现去重。`structure_score` 取 桥梁结构技术状况评分，`weight` 取 桥梁结构组成权重，`grade` 取 等级。
4. `overall`：取首个非空的 桥梁总体技术状况评分 与 综合评级。
5. 不重新计算评分，只抽取 Word 已有值。

### 5.3 真实样例预期

- `overall.total_score = 85.61`，`overall_grade = 2类`。
- `structure_parts`：上部结构 87.45/0.4/2，下部结构 86.61/0.4/2，桥面系 79.93/0.2/3。
- `evaluation_parts`：上部承重构件（3 个 score_rows）、上部一般构件、支座、翼墙耳墙等。

## 6. 照片题注扩展

### 6.1 统一文本流

`DocxBlocks` 新增 `caption_texts`：按文档顺序收集段落文本与表格单元格文本，但排除已被规则识别为病害表或评分表的表格（避免病害表“照片编号”列被当作题注）。

`find_photo_captions` 改扫该文本流，题注判定规则不变（`照片2.1-x` 为病害照片，`照片1-x`/`图1-x` 为非病害照片）。

### 6.2 未刷新域的退化行为

该样例未刷新域时，题注文本无编号（如仅“1-1#板横向裂缝”），不会被识别为题注：

1. 图片照常抽取到临时目录。
2. 病害行 `photo_numbers` 完整保留（主依据不受影响）。
3. 病害对象写 `photo_number_unmatched` warning。
4. `photos[]` 无匹配候选。

用户按流程前提 F9 刷新后，题注变为“照片2.1-1 1-1#板横向裂缝”，匹配恢复。验收接受未刷新样例的退化输出。

## 8. 测试与验收

单元测试：

1. 真实表头（部件名称/构件编号/病害位置/病害类型/病害特征/标度/照片编号）能解析病害行，字段映射正确。
2. 旧夹具表头继续通过。
3. “病害”别名不误命中“病害位置”列。
4. 完好行被跳过并产生顶层 info。
5. `severity` 取标度原文。
6. 矩阵布局 `表4.1-2` 解析出 overall/structure_parts/evaluation_parts，评价部件 score_rows 聚合正确。
7. 层级布局继续通过。
8. 表格单元格中的题注能被识别；病害表照片编号列不被当作题注。

真实样例验收（本地执行，不提交样例）：

1. `/imports/word/parse` 返回 200。
2. 病害候选 21 条，跳过 4 行完好并有 info。
3. 评分与 5.3 预期一致。
4. 输出通过 `BridgeAnnualInspectionData` 校验。
5. 全部 Python 测试通过。

## 9. 取舍

1. 列别名与布局都放在规则集中，主体解析流程不感知“辽宁”字样，后续规则（吉林国省干线等）按同一接口扩展。
2. 未刷新域的照片匹配退化可接受，不做域自动刷新——与模块 02“导入前手动 F9”前提一致。
3. 病害扣分、构件评分两列本轮不入契约，避免与 `表4.1-2` 评分主来源产生第二事实源。
4. 完好行跳过而非保留为候选，减少人工校对噪音；info 保证可追溯。
