# 模块 05 校对工作台布局优化设计

日期：2026-07-12

状态：已实施（工作台布局提交 `64673e0`）；本文保留为历史设计，后续交互以模块 05 当前基线和现有代码为准

## 1. 背景

校对工作台（`ReviewWorkspacePage`）功能已经完整，但布局停留在"文档流卡片堆叠"阶段，实际使用中有四个问题：

1. 顶部概览卡片以 12 行"标签-值"竖排铺开，占满大半个首屏，病害表格等真正的工作区被挤出屏幕。
2. 操作按钮条夹在页面中部，向下滚动校对时消失；最关键的"确认年度事实入库"与其他按钮外观相同，不突出。
3. 左侧分组导航是一张浮动小卡片，与主内容区高度不齐，存在感弱。
4. 页面整体是四五张白色圆角卡片竖排，缺少视觉层次，不像一个"工作台"。

本设计将页面骨架改为应用式工作台：页眉、侧栏、底部操作栏固定，只有内容区滚动。**只调整布局与样式（JSX 结构 + styles.css），不改动任何业务逻辑、状态管理与接口。**

## 2. 目标

1. 概览信息压缩为单行页眉 + 可折叠详情区，工作区进入首屏。
2. 操作按钮常驻可见（底部操作栏），"确认年度事实入库"为唯一主按钮。
3. 分组导航成为固定侧栏，与整体框架融为一体。
4. 页面呈现"页眉 / 侧栏 / 内容 / 底栏"的一体化工作台结构，消除卡片堆叠感。
5. 保存结果、契约校验错误、入库前检查结果统一停靠在底栏上方，出现在触发按钮旁边。
6. 修订确认由内嵌卡片改为模态弹窗。

## 3. 非目标

1. 不改动任何业务逻辑：reducer、API 调用、确认链路、只读判定、脏状态跟踪全部保持原样。
2. 不改动 `NeedsAttentionSection`、`DefectsSection`、`RatingsSection`、`RawJsonSection`、`DefectPhotoGroup`、`UnlinkedPhotosPanel`、`EvidencePanel` 的内部结构与交互（仅通过 CSS 调整其外观融入新框架）。
3. 不新增功能（不做键盘快捷键、不做主题切换、不做布局记忆）。
4. 不改动其他页面（首页、桥梁列表、桥梁详情）的布局。
5. 不改动后端与契约。

## 4. 总体骨架

### 4.1 视口高度布局

校对工作台路由（`/review` 结尾）下，页面突破现有 `.app-content-wide`（1400px 居中卡片流），改为占满整个视口的工作台：

```text
┌──────────────────────────────────────────────┐
│ 全局导航（首页 / 桥梁列表）—— 变薄，保留        │
├──────────────────────────────────────────────┤
│ ① 页眉：标题·桥名·年度·编号·状态徽章·进度徽章    │
│    └ 可折叠详情区（默认收起）                   │
├──────────┬───────────────────────────────────┤
│ ② 侧栏   │ ③ 内容区（唯一滚动区域）            │
│  需要处理 │   分组内容：表格、照片校对……        │
│  病害与照片│                                   │
│  技术评定 │                                   │
│  原始JSON │                                   │
├──────────┴───────────────────────────────────┤
│ ④ 停靠消息面板（保存结果 / 检查结果，可展开）    │
├──────────────────────────────────────────────┤
│ ⑤ 底部操作栏：取消导入 ｜ 未保存提示 ｜ 四个操作 │
└──────────────────────────────────────────────┘
```

实现方式：

- `App.tsx` 的 `AppShell` 在校对路由下改用工作台变体类名（如 `app-shell-workbench`）：去掉 32px 内边距与 880/1400px 宽度上限，根容器 `height: 100vh; display: flex; flex-direction: column`，全局导航行保留但内边距收窄。
- `.review-workspace` 改为 `display: grid; grid-template-rows: auto minmax(0, 1fr) auto auto`（页眉 / 身体 / 停靠面板 / 底栏），整体 `min-height: 0` 配合内层滚动。
- 身体行为 `display: grid; grid-template-columns: 180px minmax(0, 1fr)`；内容区 `overflow-y: auto`，是整页唯一的滚动容器；侧栏不滚动。
- 桌面端（≥1100px）整页不出现窗口级滚动条。

### 4.2 视觉基调

- 页眉、侧栏、底栏为白底，用 1px 分隔线（`#d9e0e8`）相接，不再使用圆角卡片阴影。
- 内容区白底；其内部的既有 `section.status-panel` 通过 CSS 在工作台作用域内拍平（去边框、去阴影、去圆角、内边距收窄），组件代码不动。
- 现有配色体系不变（主蓝 `#2456c9`、警示黄 `#8a6d1c`、错误红 `#a43333`）。

## 5. 页眉（①）

`OverviewHeader.tsx` 重写（文件名与组件名保留，props 不变，新增内部折叠 state）：

### 5.1 主行

一行放下（可换行兜底）：

- 标题「校对工作台」+ 桥梁名称（如 `校对工作台 · 绕阳河二号桥`）。
- 次要信息：`2026 年 · DRJL-001290`（检测年度 · 导入记录编号）。
- 导入状态徽章：待校对=黄底（沿用 `severity-warning` 配色），已确认=绿底，已取消=灰底。
- 「详情 ▾」切换按钮。
- 右端三个进度徽章：需要处理（黄）、已确认（绿）、已忽略（灰），数值来自实时 `counts`。

### 5.2 可折叠详情区

默认收起。展开后显示：

- 来源类型、解析规则。
- 病害候选数量、照片候选数量、评分项数量。
- 顶层解析 `draft.errors`（红）与 `draft.warnings`（黄）列表（原样迁移）。

当 `draft.errors` 或 `draft.warnings` 非空时，「详情」按钮上显示红/黄圆点计数提示，避免折叠后错误被忽略。

## 6. 侧栏（②）

`ReviewSidebar.tsx` 仅改样式类：

- 宽 180px，白底，右侧 1px 分隔线，不再是独立小卡片。
- 分组项去掉边框，改为"贴边导航"样式：默认灰字透明底；悬停浅灰底；选中项蓝色左边条（3px）+ 浅蓝底 + 蓝字加粗。计数右对齐。
- 四个分组与顺序不变：需要处理 / 病害与照片 / 技术状况评定 / 原始 JSON。

## 7. 内容区（③）

- 唯一滚动区域（`overflow-y: auto`），内边距约 20px。
- 「查看来源证据」按钮所在的 `.review-main-tools` 行保留，restyle 为贴近内容顶部的窄工具行（右对齐）。
- 四个分组组件按当前逻辑条件渲染，内部不动；其 `status-panel` 外观由 CSS 拍平（见 4.2）。
- 只读状态的提示不放在内容区，统一由底部操作栏承载（见 9）。

## 8. 停靠消息面板（④）

新增纯展示组件 `ReviewMessageDock.tsx`，停靠在底栏上方，承载三类既有消息（状态仍由页面层管理，只是渲染位置改变）：

1. **保存结果**（`saveMessage`）：成功为绿字单行，3 秒后自动消失（定时器在页面层，注意卸载清理）；失败为红字并列出契约校验 `issues` 明细，常驻，右侧提供「×」手动关闭（关闭即 `setSaveMessage(null)`）。
2. **入库前检查结果**（`preflight`）：默认一行摘要——通过为绿色"检查通过，可以确认入库"；未通过为黄底"仍有 N 个阻断项、M 个警告"+「展开 ▾」。展开后逐条列出 blocking_errors（红）与 warnings（黄），格式沿用现状（code：message（candidate_id））。清除时机不变（编辑草稿即失效、重跑检查即覆盖）。
3. 面板为空（无消息、无检查结果）时整行不渲染，不占高度。

「有未保存的修改」提示不进停靠面板，改进底栏（见 9）。

## 9. 底部操作栏（⑤）

`ReviewActionBar.tsx` 保持"handler 不传即禁用"的纯展示接口，新增 `dirty: boolean` 与只读横幅相关 props：

- **可编辑态**布局：左端「取消导入」（红字幽灵按钮，与其他按钮拉开距离）；中部弹性区显示未保存提示（`● 有未保存的修改，请先保存草稿再进行入库前检查`，黄字；`dirty=false` 时不显示）；右端按工作流顺序：保存草稿 → 批量确认普通评分 → 入库前检查 → **确认年度事实入库**（蓝底白字主按钮，唯一实心）。
- **只读态**：整条底栏替换为只读横幅内容——浅蓝底，`bannerText` + 入库统计（confirmResult 存在时）+「返回桥梁详情」按钮（右端）。只读提示只出现在底栏这一处。
- 底栏上边缘 1px 分隔线 + 轻微上投影，强调"浮在内容之上"。

## 10. 修订确认弹窗

`review-confirm-dialog` 由内嵌 `section` 改为模态弹窗，复用 `review-modal-backdrop` 基础设施：

- `role="dialog" aria-modal="true"`，标题、说明、勾选、备注、错误提示、按钮组内容与校验逻辑完全不变。
- 与来源证据弹窗不同：**点击遮罩不关闭**（避免误触丢失已填写的修订说明），只有「取消」按钮关闭。
- 主按钮「确认修订版入库」蓝底白字，「取消」为次按钮。

## 11. 响应式

- **≥1100px**：4.1 的视口高度工作台布局。
- **<1100px**：退回文档流——根容器高度自适应、整页滚动；底部操作栏改 `position: sticky; bottom: 0`（消息停靠面板随之贴在其上方）；页眉不固定；侧栏保持左列。
- **≤720px**：侧栏变横向滚动条状（沿用现有断点行为）；页眉主行自然换行。

## 13. 测试与验收

1. 既有单测全部保持通过（组件 props 兼容；`ReviewActionBar` 新增 props 有默认值不破坏现有用例）。
2. 新增/调整的展示组件（`ReviewMessageDock`、`ReviewActionBar` 只读态）补充渲染单测：消息分支、展开/收起、dirty 提示显隐。
3. 手工验收（用模块 05 样例数据 DRJL-001290）：
   - 1440×900 下首屏可见病害表格首行；整页无窗口级滚动条。
   - 滚动病害表格时页眉、侧栏、底栏不动。
   - 保存草稿成功提示 3 秒自动消失；校验失败明细常驻可关闭。
   - 入库前检查结果在底栏上方出现，可展开明细；编辑草稿后自动消失。
   - 修订确认以弹窗出现，点遮罩不关闭。
   - 已确认记录进入页面：底栏变只读横幅，编辑控件禁用。
   - 1000px 宽度下退回整页滚动、底栏吸底；700px 下侧栏横排。
