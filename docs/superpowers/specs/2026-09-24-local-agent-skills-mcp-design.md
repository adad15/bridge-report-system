# 本地 Agent、Skill 与 MCP 接入技术设计

> 日期：2026-09-24
> 状态：设计稿，待评审；尚未实施
> 范围：年度校对与报告生成前的只读证据助手

## 1. 背景与约束

系统当前由 C++ 主后端负责鉴权、业务编排、数据库写入和技术状况评定；Python 工具服务负责导入解析和 Word 装配；前端只访问 C++。正式报告依据已确认事实和锁定规则即时生成，当前结论文字也由确定性规则产生。AI、Milvus 和完整的跨年病害语义对比尚未实施。现状以项目上下文、运行时代码和较新的报告设计为准，早期总设计中的报告永久归档与自由章节草稿设想不作为本设计的前提。

本方案把 Agent、业务数据、检索资料和运行记录部署在本地。为回答当前问题，可向一个明确配置的大模型 API 发送最小必要内容。因此“数据留在本地”指系统持久化和工具执行在本地，不能理解为模型请求始终不离开本机。实际供应商对请求的留存和使用须在启用真实数据前核实。

沿用既有事实边界：Agent 不创建病害，不修改构件编号、数量、尺寸、评分或等级，不推定新增、消失、修复等跨年关系，不直接修改报告配置或生成的 Word。它只能解释现有预检结果、定位证据并给出待人工复核的说明。

## 2. 目标与首版范围

首版在年度校对页和报告页提供“证据助手”。用户可以询问某项预检为何阻断、某条正式观测来自何处、某项评分可追溯到哪些已保存轨迹。回答必须附可定位的实体 ID、状态和规则包版本；证据不足时说明缺口，不以模型记忆补造事实或规范条款。

首版每次只处理一个问题及本次运行中的工具调用，不建立跨会话记忆。Agent 不可用时，导入、校对、评定、报告预检和 Word 生成仍独立可用。首版不做通用 SQL、任意文件问答、照片识别、网页搜索、云端知识库、自动校对、AI 正文替换或外部 MCP 服务。Milvus 不作为前置条件。

## 3. 方案选择

| 方案 | 决定与理由 |
| --- | --- |
| Pydantic AI 独立本地进程，使用本地 Skill 和进程内只读 MCP 适配器 | 采用。与现有 Python/FastAPI 技术栈衔接，Agent 的模型等待和失败与 Office 工具进程隔离；工具可单独测试。 |
| 把 Agent 放入现有 Python 工具进程 | 进程少，但模型请求会与导入、Word 和 Office 相关工作共享故障及资源边界。 |
| 引入独立 Agent 平台 | 需要新增另一套权限、存储和运维边界，首版收益不足以覆盖复杂度。 |

Pydantic AI 是 Agent 运行框架，不包含大模型。首版只配置一个指定模型 API，不自动回退其他模型，不使用额外模型网关。供应商、模型标识、API 地址、密钥和留存要求由部署配置确定。模型必须满足工具调用与结构化输出的兼容性验证。

## 4. 部署与组件

数据流：React 页面 → C++ 主后端 → 本地 Agent 进程 → 进程内只读 MCP 工具 → C++ 内部证据接口；Agent 进程唯一允许的外连是指定大模型 API。现有 Python 工具服务继续独立处理导入和报告文档。

1. C++ 是前端唯一业务入口。收到提问后，它验证用户、桥梁与年度权限，为本次运行提供短期、限范围的上下文。Agent 不拿用户的完整登录凭据，也不拿数据库连接。
2. Agent 是单独的本地 Python 进程，只监听环回地址；示例端口为 18082，实际值由配置决定。它负责 Skill 加载、模型调用、工具编排、时限、用量限制和结构化输出校验。
3. 进程内 FastMCP 适配器只包装 C++ 的内部只读证据接口，不对外开放 MCP 端口。每次内部调用仍由 C++ 校验短期上下文、授权年度、目标实体和结果上限。Agent 不直接访问 PostgreSQL 或归档目录。
4. 首版工具限定为：读取预检错误与警告、读取单条正式观测摘要、读取指定年度或构件的评分轨迹摘要、读取报告生成前检查。各工具均有明确参数、字段白名单、分页和大小上限；不存在通用 SQL、任意 URL、任意路径或写入工具。

对 C++ 内部证据接口采用单独的服务凭据与短期请求上下文，限制仅本机可达。即使模型给出越界的工具参数，C++ 仍拒绝访问；提示词和 Skill 不能代替鉴权。

### 4.1 接口契约

前端新增按年度限定的查询入口：POST /api/inspection-years/{inspection_year_id}/assistant/query，请求包含 question 和客户端请求标识。C++ 在调用 Agent 前解析当前登录用户及桥梁/年度授权，不接受前端自行声明的用户 ID、允许工具或模型地址。成功响应包含 answer、evidence、review_required 和 limitations；助手故障返回独立错误码及可重试提示，不改变现有报告接口的状态。

C++ 调用本机 Agent 的 POST /internal/agent/run，传入问题、请求标识及短期不透明运行凭据。该凭据绑定用户、桥梁、年度、允许的只读工具和过期时间。Agent 调用证据接口时须携带凭据；C++ 每次验证凭据、权限和查询参数，且只返回已经裁剪的结构化 JSON。凭据只在本次运行内使用，不进入模型提示词、工具结果或审计正文。

## 5. Skill 设计

使用官方 pydantic-ai-harness[skills]，只扫描明确配置且经过审核的本地目录。首版两项 Skill：preflight-explanation 规定预检问题的解释顺序及引用要求；assessment-evidence 规定评分轨迹的核查和证据表达方式。Skill 只写流程说明和判断边界，不放业务记录、密钥、规范全文或可执行命令。

加载的 Skill 正文会进入模型请求。发布时记录 Skill 版本与文件摘要，只允许可信维护者修改。Harness 当前只自动读取 SKILL.md 的指令，不自动读取附带的 references、assets，也不执行 scripts；Skill 的元信息不构成工具权限。依赖版本固定，升级前核查行为变化。

## 6. MCP 设计

Pydantic AI 以本地客户端方式连接进程内 MCP 适配器。模型提出工具调用后，实际调用在本机执行；返回值可能随下一轮模型请求发给指定模型 API。首版不启用由模型供应商直接连接 MCP 的原生模式，不把 MCP 服务暴露为公网 URL。

MCP 是受控工具接口，不是数据脱敏措施。工具的授权、字段裁剪和返回大小限制放在 C++；Agent 在发送模型请求前再检查初始问题、Skill 正文、工具定义、工具返回和本轮消息历史。以后确需供其他本地程序复用时，再单独评估环回 HTTP MCP 服务。

## 7. 输出与外发数据

模型请求可能包含系统指令、已加载的 Skill、用户问题、工具定义、工具结果和本轮历史。默认只允许短结构化事实、来源 ID 和必要的规则身份进入请求；不得默认发送完整数据库行、原始 Word、照片二进制、文件路径、账号信息或密钥。结果超限时要求缩小问题范围，不自动分批上传全量资料。

Agent 返回固定结构：回答、证据列表、是否需要人工复核、限制说明。证据包含实体类型、ID、状态和版本。C++ 再验证证据属于当前授权范围；前端标为“AI 辅助说明”，可跳转原始记录。回答中的编号、数量、尺寸和等级必须能与本次工具结果核对；无法核对的具体事实不作为已证实内容展示。Agent 结果不进入正式病害、评定、报告配置或 DOCX。

完整请求和响应正文默认不写入应用日志。本地审计只记录用户、范围、工具、模型标识、时间、用量、结果状态及外发内容摘要。诊断原文需要单独开启有期限的本地诊断模式。Agent 进程的出站网络仅允许指定模型 API；不启用网页搜索、第三方 MCP、云端追踪或模型网关。

## 8. 故障与安全

模型超时、限流、不可达、MCP 错误、输出结构错误和 Agent 进程退出时，前端显示助手失败状态，原业务流程不降级为模型推断结果。每次运行限制模型请求次数、工具调用次数、工具结果大小、总时长和并发数。

来源报告、导入文字及工具返回均视为不可信内容。其中要求改变规则、调用更多工具或披露数据的文字不能扩大授权。授权由 C++ 执行，Agent 进程使用最小权限账户。Agent 模块只能保证自身不将数据发给指定模型 API 之外的外部服务；服务商如何留存已收到的内容取决于其协议、配置及实际部署。

## 9. 验证与实施顺序

先实现并测试 C++ 内部只读证据接口，再增加本地 Agent 进程、MCP 适配器和两项已审核 Skill，然后接入前端只读入口。使用假模型捕获所有请求，核对用户问题、Skill、工具返回及历史中没有越权字段、原始文档、照片或密钥。测试跨用户、跨桥梁、跨年度、过期上下文和越界工具参数均被拒绝。

使用现有 2026 年度隔离验收数据抽样核对引用和评分轨迹；2024、2025 年度尚无同等级正式入库与报告验收，不作为已验证事实样例。注入模型与 MCP 故障，确认原有报告流程继续可用。真实模型灰度前完成供应商请求留存、网络出口和代理日志核查；灰度期间人工抽查回答及来源。

后续规范检索、相似历史写法检索和受控润色分别设计资料版本、引用及事实校验规则。框架支持更多工具并不构成开放数据库、文件系统或互联网权限的理由。
