# 河床构件台账生成与规范包版本化设计

> 日期：2026-08-14
>
> 状态：已确认并实施
>
> 分支：`codex/06-6-interaction-redesign`

## 1. 背景

H21 的构件分类、权重和病害指标一直包含“河床”，但截至技术状况规范包 1.0.3，`h21.component.lower.riverbed` 的 `generatable` 为 `false`。因此河床能参与系统评定，却不会进入创建桥梁时的初始构件台账向导。

此前的临时实现通过产品目录字段 `manually_selectable` 绕过这一限制。该做法破坏了既有架构约束：某桥型可以生成哪些部件，应由所选规范包 taxonomy 的桥型适用范围、结构分部和 `generatable` 共同决定，taxonomy 是唯一准入真值。

## 2. 决策

1. 发布 `JTG_T_H21_2011/1.0.4`，从 1.0.3 派生，只把河床的 `generatable` 改为 `true`。
2. 不修改已发布的 1.0.3；1.0.3 的清单、入口文件和摘要保持原样。
3. 发布 `organization-bridge/2.0.3`，树结构、映射和评分语义与 2.0.2 相同，H21 来源锁定升级为 1.0.4。
4. 删除 `CatalogPart::manually_selectable` 及路由中的绕过逻辑。所有部件统一服从 taxonomy 的 `generatable`。
5. 河床作为用户可选的全桥级单一台账对象，不按孔、墩、台或数量批量展开。

## 3. `generatable` 语义

`generatable` 是构件台账生成准入标志：

- `true`：当类别同时适用于所选桥型、结构分部与产品目录一致时，类别对应的产品部件可以出现在台账向导中并接受生成请求。
- `false`：类别不得通过初始台账生成端点显示或生成，产品目录不能自行放宽。

该字段不是评分开关。类别是否参与技术状况评定，由评定树、权重、病害指标和评分规则决定。河床在 1.0.3 中虽为 `generatable=false`，其评分权重和病害指标仍然有效；1.0.4 不改变任何评分数值、公式、标度或等级边界。

## 4. 河床产品部件

| 字段 | 值 |
| --- | --- |
| `part_key` | `lower.riverbed` |
| 默认名称 | 河床 |
| H21 类别 | `h21.component.lower.riverbed` |
| 结构分部 | `substructure` |
| 编号模板 | `{name}` |
| 数量输入 | 无 |
| 展开结果 | 勾选后全桥生成一个条目 |
| 默认状态 | 不勾选 |
| 适用桥型 | H21 taxonomy 声明的全部六种桥型 |

生成条目的 `component_number`、`site_name` 和 `site_component_type` 默认均为“河床”，用户修改现场名称时 `{name}` 随之变化。

## 5. 版本与兼容性

- H21 1.0.4 的包身份和内容摘要与 1.0.3 不同，启动同步按新版本插入，不需要数据库结构迁移。
- 评定树 2.0.3 锁定 H21 1.0.4 和既有 JTG 5120 1.0.0。已锁定旧评定树/旧 H21 的项目继续按原版本重现，不被自动改写。
- 创建新桥梁时，可用技术状况包按版本降序显示，默认选择最新包；存在多个版本时，下拉项必须显示版本号，仍允许显式选择历史包。
- 新包发布后，下部结构目录相对旧包增加河床；旧包仍因 `generatable=false` 不显示河床。

## 6. 生成与发布约束

- `standards/technical-condition/jtg-t-h21-2011/1.0.4` 从 1.0.3 复制，除 manifest 版本/摘要和河床准入标志外不得出现内容漂移。
- `standards/rating-tree/organization-bridge/2.0.3` 必须由 `bridge_report_tools.rating_tree.package_generator` 从受控来源生成，不手工编辑生成产物。
- 生成器从传入的 H21 包目录推导 `sources.json` 的版本引用，默认目标为 H21 1.0.4 和评定树 2.0.3。
- 两个新包都必须通过加载器的稳定摘要校验。

## 7. 验收标准

1. H21 1.0.4 能加载，manifest 摘要匹配，河床 `generatable=true` 且适用于六种桥型。
2. H21 1.0.3 保持未修改，河床仍为 `generatable=false`。
3. 评定树 2.0.3 能加载和编译，节点数及 403 条来源映射与 2.0.2 一致，H21 来源指向 1.0.4。
4. 部件目录不再包含 `manually_selectable`；任意 `generatable=false` 类别均无法显示或生成。
5. 河床勾选后只生成一个全桥级条目，前端预览与后端结果一致。
6. 多个规范包同时可用时，新建桥梁默认选择最新版本并显示明确版本号。
7. C++ 规范包、评定树、目录、路由和生成器测试通过；Python 生成器测试通过；前端向导和创建桥梁测试通过。

## 8. 文档关系

本文是 2026-07-21 构件编号设计和全桥型向导实施计划的后续补充。原文中“编号规则不触发规范包发布”的结论仍适用于普通产品编号调整；本次发布改变的是 taxonomy 的生成准入元数据，因此必须走不可变规范包的新版本流程。
