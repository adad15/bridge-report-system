# 辽宁国省干线 Word 规则模块化设计

日期：2026-07-07

## 1. 背景

模块 04 已实现 `.docx` Word 导入原型，但第一版规则分散在解析代码中：

1. `docx_reader.py` 写死章节识别。
2. `defect_tables.py` 写死病害表识别。
3. `photo_extractor.py` 写死照片题注正则。
4. `rating_tables.py` 写死评分表识别。

实际测试 `辽宁国省干线桥梁检测项目` 非正式报告后，发现后续规则会按地区、路线类型或报告模板变化。继续把规则散落在主体解析代码里，会导致每次优化模板规则都影响导入主流程。

本设计将 Word 解析规则从主体解析流程中抽离，第一套规则命名为 `辽宁国省干线`。

## 2. 目标

本设计目标：

1. 将 Word 导入规则模块化，便于后续新增或修改规则。
2. 第一版只实现 Python 代码级规则模块化，不做 JSON/YAML 外部配置化。
3. 规则由用户选择，不由 Python 自动判断模板。
4. 建立 `辽宁国省干线` 规则集。
5. 删除旧的泛化硬编码规则，不再以“第二章/第四章”作为业务规则核心。
6. 保持模块 04 的输出契约仍为 `BridgeAnnualInspectionData`。

本设计不负责：

1. 前端规则选择页面的完整实现。
2. 根据规则选择刷新桥梁库的前端或 C++ 业务逻辑。
3. 数据库写入。
4. 正式报告正文抽取。
5. OCR、PDF、`.doc` 兼容。

## 3. 用户选择规则

规则不做自动模板识别。

后续用户在前端选择规则类型，例如：

```text
辽宁国省干线
吉林国省干线
辽宁鹤大高速
```

前端或 C++ 根据用户选择刷新对应桥梁库。Python 工具服务不关心桥梁库筛选逻辑，只接收 C++ 传入的规则名。

模块 04 的 Python 请求需要新增字段：

```json
{
  "rule_profile": "辽宁国省干线"
}
```

`rule_profile` 用于选择规则集。第一版只支持：

```text
辽宁国省干线
```

如果传入未知规则，Python 返回解析失败：

```json
{
  "code": "unsupported_rule_profile",
  "message": "不支持的 Word 解析规则：xxx"
}
```

## 4. 规则模块架构

建议新增目录：

```text
tools-python/bridge_report_tools/importers/word_rules/
  __init__.py
  rule_set.py
  common.py
  liaoning_trunk.py
```

文件职责：

| 文件 | 职责 |
| --- | --- |
| `rule_set.py` | 定义规则集接口、规则选择入口和错误 |
| `common.py` | 通用文本清洗、表题匹配、表头匹配、编号解析工具 |
| `liaoning_trunk.py` | `辽宁国省干线` 规则实现 |

主体解析模块职责调整：

| 文件 | 调整后职责 |
| --- | --- |
| `word_importer.py` | 主流程编排，根据 `rule_profile` 选择规则集 |
| `docx_reader.py` | 读取 `.docx` 段落、表格、图片顺序，不写业务模板规则 |
| `defect_tables.py` | 根据规则集识别病害表并解析病害行 |
| `photo_extractor.py` | 根据规则集识别病害照片题注并匹配图片 |
| `rating_tables.py` | 根据规则集识别评分表并解析评分 |

主流程变为：

```text
WordImportRequest
  -> select_rule_set(rule_profile)
  -> read_docx_blocks()
  -> parse_defect_tables(document.tables, rule_set)
  -> parse_rating_tables(document.tables, rule_set)
  -> extract_and_match_photos(docx_path, document, defects, output_dir, rule_set)
  -> BridgeAnnualInspectionData
```

## 5. 辽宁国省干线规则

规则显示名：

```text
辽宁国省干线
```

规则代码名建议：

```text
liaoning_trunk
```

适用输入：

```text
辽宁国省干线桥梁检测项目的非正式 Word 报告 `.docx`
```

本规则不从模板正文自由抽取病害事实，只从指定可信表格抽取。

## 6. 病害表规则

### 6.1 可信来源

`辽宁国省干线` 规则只从以下三张表抽取病害候选：

```text
表2.1-1  上部结构病害检查表
表2.2-1  下部结构病害检查表
表2.3-1  桥面系病害检查表
```

对应结构分部：

| 表题 | `structure_part` |
| --- | --- |
| `表2.1-1 上部结构病害检查表` | `上部结构` |
| `表2.2-1 下部结构病害检查表` | `下部结构` |
| `表2.3-1 桥面系病害检查表` | `桥面系` |

`5.1.1 桥梁外观检查结论` 不作为病害候选来源。

### 6.2 表格识别

表格识别优先使用表题。

表题匹配规则：

1. 忽略多余空格。
2. 支持全角和半角空格。
3. 必须包含表号 `表2.1-1`、`表2.2-1` 或 `表2.3-1`。
4. 必须包含对应结构分部和 `病害检查表`。

示例可接受表题：

```text
表2.1-1  上部结构病害检查表
表2.1-1 上部结构病害检查表
表2.2-1  下部结构病害检查表
表2.3-1  桥面系病害检查表
```

表头匹配作为二次校验。表头应包含病害行所需字段，例如：

```text
构件
部位
位置
病害
数量
尺寸
照片编号
```

真实表头可能存在同义列，规则集中维护列名别名。

### 6.3 解析失败规则

如果三张病害表全部未识别到：

1. `defects=[]`
2. 顶层 `errors[]` 写入 `defect_tables_not_found`
3. 导入仍可继续尝试评分和图片解析

如果只缺少其中某一张表：

1. 已识别表正常输出病害候选。
2. 顶层 `warnings[]` 写入缺失表提示。

## 7. 病害照片规则

### 7.1 病害照片编号

`辽宁国省干线` 规则只把以下编号视为病害照片：

```text
照片2.1-1
照片2.1-2
照片2.2-1
照片2.2-2
照片2.3-1
照片2.3-2
```

抽取后只保存编号本体：

```text
2.1-1
2.2-1
2.3-1
```

支持格式：

```text
照片2.1-1
照片 2.1-1
2.1-1
照片2.1-1、2.1-2
照片2.1-1/2.1-2
```

### 7.2 非病害照片

以下照片不作为病害照片：

```text
照片1-1
照片1-2
照片1-3
图1-1
```

这些通常属于桥梁概况、全景照或示意图，不进入 `photos[]` 病害照片候选。

如果后续需要归档非病害照片，应另建报告附件或桥梁概况图片流程，不放入模块 04 的病害照片候选。

### 7.3 图片匹配

图片匹配仍以病害表照片编号为主依据：

```text
病害表照片编号
  -> 病害照片题注编号
  -> 图片候选
```

匹配成功：

```text
match_status = 高置信候选
linked_defect_candidate_id = defect_xxxx
```

病害表引用了照片编号，但 Word 中未找到对应病害照片题注：

```text
病害对象写 photo_number_unmatched warning
```

Word 中存在病害照片题注，但病害表未引用：

```text
照片对象保留，match_status = 未关联
照片对象写 photo_not_referenced_by_defect warning
```

## 8. 评分规则

### 8.1 可信来源

`辽宁国省干线` 规则只从以下表格抽取评分：

```text
表4.1-1 桥梁部件权重计算表
表4.1-2 总体技术状况评定表
```

其中：

| 表格 | 用途 |
| --- | --- |
| `表4.1-1 桥梁部件权重计算表` | 权重来源或评分校验来源 |
| `表4.1-2 总体技术状况评定表` | `ratings.overall`、`ratings.structure_parts`、`ratings.evaluation_parts` 主来源 |

不从以下位置抽取评分作为主数据：

```text
桥梁技术状况等级综合评定正文
附录1 桥梁技术状况评定表
桥梁检测情况一览表中的检测结论
```

这些位置可作为后续校验来源，但第一版不顶替 `表4.1-2`。

### 8.2 表格识别

表格识别优先使用表题。

可接受表题：

```text
表4.1-1 桥梁部件权重计算表
表4.1-2 总体技术状况评定表
```

表题匹配规则：

1. 忽略多余空格。
2. 支持全角和半角空格。
3. 必须包含表号。
4. 必须包含核心名称。

### 8.3 评分抽取

`表4.1-2 总体技术状况评定表` 负责输出：

```text
ratings.overall.total_score
ratings.overall.overall_grade
ratings.structure_parts[]
ratings.evaluation_parts[]
```

不重新计算评分，只抽取 Word 中已有值。

`表4.1-1 桥梁部件权重计算表` 第一版不单独输出到契约字段；它用于：

1. 支持 `表4.1-2` 中权重字段理解。
2. 后续作为评分校验来源。

如果 `表4.1-2` 未识别到：

```text
rating_table_not_found
```

并且不使用 `附录1` 或正文评分顶替。

## 9. 读取层要求

这份真实 Word 测试中，当前 `python-docx` 基础读取只读到部分表格，未读到用户指定的：

```text
表2.1-1
表2.2-1
表2.3-1
表4.1-1
表4.1-2
```

因此实施时必须先增强读取层诊断：

1. 确认这些表是否存在于 `.docx` 主文档 XML。
2. 确认表是否在文本框、嵌套表、页眉页脚、域结果或其他结构中。
3. 输出调试用表题、附近段落、表头和表格序号。
4. 在规则解析前确保读取器能把目标表交给规则模块。

读取层只负责“把 Word 内容读出来”，不写 `辽宁国省干线` 业务规则。

## 11. 错误和警告

新增或调整错误码：

| code | 位置 | 含义 |
| --- | --- | --- |
| `unsupported_rule_profile` | HTTP 400 | 传入未知规则 |
| `liaoning_trunk_defect_table_missing` | 顶层 warning | 缺少某一张辽宁国省干线病害表 |
| `defect_tables_not_found` | 顶层 error | 三张病害表全部未找到 |
| `liaoning_trunk_rating_weight_table_missing` | 顶层 warning | 未找到表4.1-1 |
| `rating_table_not_found` | HTTP 400 或顶层 error | 未找到表4.1-2，且不能用附录或正文顶替 |
| `photo_number_unmatched` | 病害对象 warning | 病害表照片编号未匹配到病害照片 |
| `photo_not_referenced_by_defect` | 照片对象 warning | 病害照片未被病害表引用 |

## 12. 测试策略

单元测试需要覆盖：

1. `rule_profile="辽宁国省干线"` 能选择规则集。
2. 未知 `rule_profile` 被拒绝。
3. 能识别 `表2.1-1 上部结构病害检查表`。
4. 能识别 `表2.2-1 下部结构病害检查表`。
5. 能识别 `表2.3-1 桥面系病害检查表`。
6. `照片2.1-1` 被识别为病害照片编号。
7. `照片1-1` 不进入病害照片候选。
8. 能识别 `表4.1-1 桥梁部件权重计算表`。
9. 能识别 `表4.1-2 总体技术状况评定表`。
10. 未找到 `表4.1-2` 时不使用附录或正文兜底。
11. 主流程输出仍通过 `BridgeAnnualInspectionData` 校验。

真实样例验收需要覆盖：

1. 对用户提供的辽宁国省干线非正式报告执行读取层诊断。
2. 确认目标表是否被读取。
3. 如果目标表未被读取，先修读取层，再修规则层。

## 13. 取舍

### 13.1 不做自动模板识别

用户会在业务流程中点选规则类型。这样更符合桥梁库按规则刷新、后台明确规则来源的流程，也避免 Python 根据少量关键词误判模板。

### 13.2 不抽 5.1.1 正文病害

`5.1.1 桥梁外观检查结论` 是正文总结，不作为第一版病害事实来源。辽宁国省干线规则只从三张病害检查表抽取病害。

### 13.3 不把照片1-x当病害照片

`照片1-1` 等属于桥梁概况照片，不参与病害匹配。病害照片规则聚焦 `照片2.1-x`、`照片2.2-x`、`照片2.3-x`。

### 13.4 不用附录1或正文评分兜底

评分主来源是 `表4.1-2 总体技术状况评定表`。`附录1` 和正文评分不顶替它，避免把摘要或附录误当作主评分表。

### 13.5 第一版不做配置化

规则先用 Python 代码模块实现。等多个地区规则稳定后，再考虑把关键词、表题、列名别名迁移到 JSON/YAML。

## 14. 后续扩展

后续新增规则时，按同一接口增加：

```text
吉林国省干线
辽宁鹤大高速
```

每个规则集独立定义：

1. 病害表标题。
2. 结构分部映射。
3. 照片编号格式。
4. 评分表标题。
5. 表头别名。
6. 评分字段映射。

主体解析流程不因新增规则而改变。
