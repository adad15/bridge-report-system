# 2026-07-24 设计：构件绑定的批量查找替换

> 日期：2026-07-24
>
> 分支：`codex/06-5-interaction-redesign`
>
> 触发背景：真实报告里大量构件编号与台账写法**系统性不同**——如报告写"第32孔桥面"，台账按《构件编号规则》生成的是"32#跨桥面铺装"，导致"桥面铺装"整组 26 行全部未匹配。差异有规律，但目前只能逐行搜索、逐行选择、绑定 26 次。

## 1. 问题

匹配器要求**部件类别 + 归一化编号精确一致**。而 `normalize_component_number` 只消除表面差异（全角转半角、去空格、转小写、去尾部 `#`），**处理不了结构性差异**：`第32孔桥面` 与 `32#跨桥面铺装` 归一化后仍然对不上。

这类差异按部件成规律：桥面铺装是一种写法差异，铰缝可能是另一种。逐行手工绑定的工作量与构件数成正比，且全是重复劳动。

## 2. 目标与非目标

### 2.1 目标

- 用一条**带数字通配的查找替换规则**，一次处理整组同类差异。
- 应用前给出**可核对的预览**：哪些行会绑到哪个构件、哪些行会被跳过及原因。
- 不改变既有绑定语义，撤销沿用现有的"取消绑定"。

### 2.2 非目标

- **不改写报告原文**。`component_number` 的原文保真有断言锁定（`test_word_import_repository.cpp`），替换只用于**查找台账目标**，不落库、不覆盖原文。
- 不引入正则。查找串里除 `*` 外一律按字面处理，用户无需了解转义。
- 不做规则的保存与跨导入复用（YAGNI；每次导入各绑各的，与绑定模块既有取舍一致）。
- 不改匹配器的自动匹配逻辑。本功能是人工批量操作，不影响导入时的自动对号。

## 3. 交互

入口为**分组表头上的「批量替换」按钮**（如"桥面铺装 共 26 · 未匹配 26"一行右侧）。逐组处理，因为写法差异按部件成规律，一条规则通常只适用于一个部件。

对话框内两个输入 + 一张预览表：

```
查找      第*孔桥面
替换为    *#跨桥面铺装

┌ 预览（参与 26 行：未匹配 26 · 歧义 0）──────────────┐
│ 第32孔桥面 → 32#跨桥面铺装   ✓ 将绑定               │
│ 第33孔桥面 → 33#跨桥面铺装   ✓ 将绑定               │
│ …                                                   │
│ 第7孔桥面  → 7#跨桥面铺装    ✗ 台账中无此编号        │
└─────────────────────────────────────────────────────┘
        将绑定 25 行 · 跳过 1 行      [取消] [应用]
```

### 3.1 通配语义

- `*` 匹配**一段连续数字**（等价 `\d+`），至少一位。
- 查找串中的其余字符**按字面匹配**，不做正则解释。
- 替换串中第 k 个 `*` 取查找串中第 k 段匹配到的数字（**按位置对应**）。
- 替换串的 `*` 个数**可以少于**查找串（多余的捕获不使用），**不得多于**查找串——多于时无从取值，属非法模式。
- 模式匹配作用于**行上显示的报告原文**，不预先归一化。这样"所见即所匹配"，行内若有异常空白会落到"不符合查找模式"并在预览中显形，而不是被静默吞掉。

## 4. 匹配与应用语义

### 4.1 参与范围

**仅 `unmatched` 与 `ambiguous` 两种状态的行参与。** 已绑定、已标记缺失的行不参与也不受影响——守住"已经核对过的结果不会被批量操作意外推翻"。确需重绑的行，先"取消绑定"使其回到 `unmatched`，即可纳入下一次批量替换。

### 4.2 单行判定

对每个参与行，按查找模式转换后，用 `normalize_component_number` 归一化，与台账中**全部启用构件**的编号（同样归一化）比对：

| 情形 | 预览标记 | 应用时 |
| --- | --- | --- |
| 不符合查找模式 | ✗ 不符合查找模式 | 跳过 |
| 恰好 1 个命中 | ✓ 将绑定 → 目标编号 | 绑定 |
| 0 个命中 | ✗ 台账中无此编号 | 跳过 |
| ≥2 个命中 | ✗ 台账中有多个同号构件 | 跳过 |

**查台账时不限定部件类别**，只按归一化编号比对。这是有意的取舍：限定类别需要把报告部件名映射到规范类别（该对照表在后端 `ComponentCategoryLexicon`，前端没有），而不限定的代价仅是"跨部件编号恰好同名时会判为歧义并跳过"——**宁可跳过让人工处理，不可绑错**。

### 4.3 应用

只绑"恰好 1 个命中"的行；其余原样保留，用户可改模式再来一次或手工处理。

绑定只写 `bridge_component_id`（与手工绑定完全一致），**不触碰报告原文**。因此撤销即现有的行内"取消绑定"，不需要新的撤销机制。

## 5. 接口与落点

### 5.1 预览：纯前端

绑定页已把台账 `entries` 加载在手（手工搜索就用它），预览所需的全部数据本地即有。填模式即时出结果，**不需要新增查询接口**。

### 5.2 应用：新增批量端点

`POST /api/import-records/{id}/component-binding/bind-batch`

请求体为一组目标：

```json
{ "targets": [
  { "part_name": "桥面铺装", "component_number": "第32孔桥面", "bridge_component_id": "…" }
] }
```

返回更新后的 `overview`（与既有三个绑定端点同形）。

不复用现有单条 `bind` 循环调用的原因有二：26 行会产生 26 次往返、每次回传完整 overview；且中途失败会留下"绑了一半"的状态，用户无从判断哪些生效了。

后端复用 `ImportBindingRepository` 既有的"待校对相读改 `parsed_result_json`"路径，在一次读改写中循环处理全部目标。

## 6. 错误处理

- **模式非法**（替换串 `*` 多于查找串）：对话框内即时提示，"应用"按钮禁用。
- **无可绑行**（预览中"将绑定"为 0）："应用"按钮禁用。
- **批量端点原子性**：任一目标非法（部件名/编号在该导入中不存在、构件不在台账中、导入不处于"待校对"）则**整批不写**，返回首个出错目标及原因。避免部分成功造成的不确定状态。
- 应用后对话框关闭，行列表按新状态重绘；被跳过的行仍留在未匹配区，可再次操作。

## 7. 测试

- **通配展开**：单 `*`、多 `*` 按位置对应、替换 `*` 少于查找、字面字符不被当作正则（如查找串含 `.`、`(`）。
- **模式校验**：替换 `*` 多于查找 → 判非法。
- **分级判定**：不符合模式 / 0 命中 / 1 命中 / 多命中 四种情形各一例。
- **参与范围**：已绑定与已标记缺失的行不出现在预览、应用后状态不变。
- **批量端点**：正常批量写入；任一目标非法时整批回滚且返回出错项。
- **前端**：预览计数正确；应用后行从未匹配区消失（与"默认只显示待处理行"的既有行为一致）。

## 8. 已知局限

- 跨部件编号同名时判为歧义并跳过，需人工处理。属有意取舍（见 §4.2）。
- 规则不保存，下次导入需重填。若日后发现同一批规则反复使用，再考虑固化为匹配器的等价写法规则——那是改自动匹配，与本功能的人工批量定位不同，应另行设计。
- 本功能不解决**范围写法**（如 `1-1#板~1-25#板` 一行代表 25 个构件）。那需要一条病害拆成多条，涉及数据形态变更，与本设计正交。
