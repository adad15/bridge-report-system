# JTG/T 5230—2026 评定参数包与评分器设计

日期：2026-10-27　状态：待评审　分支：`feature/jtg-5230-2026-evaluator`

原文：规范原文库「公路桥梁技术状况评定标准 · 2026版」（JTG/T 5230—2026，2026-11-01 实施）。原文是扫描件（116 页，无文字层），下文引用的条文号和页码都对照该文件。正文页码 = PDF 页码 − 6。

## 1 背景与本期范围

5230—2026 是对 JTG/T H21—2011 的全面修订（前言）：桥型细化为 5 大类 21 种评定类型；构件状况分为缺损（耐久性、结构性）、功能、影响三方面；评定流程改为“构件 → 桥跨 → 全桥”，并新增桥跨层和评定单元。现有 H21 评分器（`H21Evaluator`，构件分 → 部件 → 上部/下部/桥面系 → 全桥）和评定树都不能沿用。

整个 5230 落地拆成五个子项目，本期只做其中两个：

| 子项目 | 内容 | 本期 |
| --- | --- | --- |
| 1 评定参数包 | 附录 B 部件组成与权重、表 3.3.3 主要构件、三张分类界限、单项控制指标、构件养护对策 | 做 |
| 3 评分器 | 构件、桥跨、全桥三层计算，含评定单元与单项控制 | 做 |
| 2 指标库 | 第 4～15 章各类缺损、功能、影响指标及标度描述（约 75 页表格） | 后续 |
| 4 病害对应与录入 | 由病害推出耐久性 / 结构性标度；录入功能状况、影响状况、是否影响桥梁安全 | 后续 |
| 5 接入业务 | 桥跨归属、评定单元划分、年度按规范切换、结果展示、报告（附录 C）、全桥养护对策（JTG 5120） | 后续 |

本期交付：一个可被加载和校验的规则包，加一个用测试证明公式实现正确的 C++ 评分器。不改数据库、HTTP 接口和界面，H21 的行为不变。

## 2 评定方法摘要（实现依据）

### 2.1 构件（3.2，PDF 12～15）

| 量 | 取值 | 规则 |
| --- | --- | --- |
| 耐久性缺损 EDDI | 0、1、2 | 按构件材料评（第 4 章），多项取最大 |
| 结构性缺损 ESDI | 0、1、2、3 | 按构件类型评（第 5～12 章），维修加固构造按第 13 章计入原构件 |
| 缺损状况 EDI | 0～3 | max(EDDI, ESDI)；标准或设计要求设置而未设置的构件取 3（3.2.2-5） |
| 功能状况 EFI | 0、1、2 | 第 14 章，多项取最大 |
| 影响状况 EAI | −1、0、1 | 只评主要构件（第 15 章），多项取最大 |
| 技术状况标度 ECI | 0～5 | ECI = EDI + EFI + EAI，≥5 取 5（式 3.2.5） |

技术状况等级 ECL（表 3.2.6）：ECI 为 0、1 → 1 类（优）；2 → 2 类（良）；3 → 3 类（中）；4 → 4 类（次）；5 → 5 类（差）。

养护对策（表 3.5.2）：1 类日常养护；2 类日常养护、预防养护；3 类预防养护、修复养护；4、5 类修复养护。

### 2.2 桥跨（3.3，PDF 15～16）

BSCI(i) = 100 − Σⱼ CI(j) · ω · γ / 5（式 3.3.1），保留一位小数。

- CI(j)：第 i 跨第 j 个部件中最差（最大）的构件 ECI；
- ω：部件权重，γ：所在结构（桥面系、上部结构、下部结构、附属构造）的影响系数，均见附录 B；
- 相邻两跨共用的桥墩、支座、伸缩装置等，两跨都要计入；拼宽结构中新旧结构共用的构件，各评定单元都要计入。

桥跨等级 BSCL（表 3.3.2）：(90, 100] 1 类，(75, 90] 2 类，(60, 75] 3 类，(40, 60] 4 类，[0, 40] 5 类。

主要构件改判（3.3.3）：主要构件等级为 4、5 类**且影响桥梁安全**时，该跨按该构件的最差等级评定；此时后续计算中该跨指数取该等级上限（4 类 60，5 类 40，条文说明）。常用桥型的主要构件见表 3.3.3。

### 2.3 全桥（3.4，PDF 16～17）

- 单跨：桥跨等级和指数即全桥结果（3.4.1）。
- 多跨且各跨等级一致：全桥等级即该等级，指数取各跨指数算术平均（3.4.2）。
- 多跨且等级不一致：全桥等级取最差桥跨；指数按式 3.4.3：

  BCI = BSCIₘᵢₙ + (BSCIₗᵢₘ − BSCIₘᵢₙ) · (平均 BSCI − BSCIₘᵢₙ) / (BSCIₘₐₓ − BSCIₘᵢₙ)

  BSCIₗᵢₘ 按最差桥跨等级取：2 类 90，3 类 75，4 类 60，5 类 40。保留一位小数。
- 划分评定单元时，以最差单元的结果作为全桥结果（3.4.4）。
- 出现 3.4.5 所列 16 项单项控制指标中任一项时，全桥等级评为 5 类；报告中同时说明分层综合评定结果和单项控制结果（条文说明）。

### 2.4 附录 B 部件组成与权重（PDF 98～110）

- 表 B.1.1：梁桥 7 种、拱桥 7 种、组合体系拱桥 3 种、悬索桥 2 种、斜拉桥 2 种，共 21 种评定类型。
- 每种评定类型一张表：每个结构一个 γ（四个结构合计 1），每个结构下列部件及 ω（同一结构内合计 100）。
- 部分表给出多套权重。例如表 B.3.5、B.3.6（箱形拱、双曲拱）第二列是不设伸缩装置时的权重：桥面铺装 50、护栏及人行道 30、排水系统 20。这些是规范直接给定的值，不是按比例换算出来的。
- B.1.3：全桥无须设置的部件，其权重在所在结构内按比例分给其他部件，全桥各跨用统一权重；只是个别桥跨没有的部件不再分配，该部件标度取 0（条文说明）。
- 表下的注规定构件怎么划分（如“箱形拱桥主拱圈每跨划分为 1 个构件”“悬索桥加劲梁每两个吊点之间划分为 1 个构件”），本期作为说明保存。
- 部件随桥型不同：地锚式悬索桥下部结构有“锚碇及锚固系统”；同一部件在不同表里叫法略有出入（表 B.6.2 写“基础”，表 B.6.3 写“墩台基础”，注明“基础包括墩台基础和索塔基础”）。转录时保留各表原名，用同一个部件 id。

### 3.3 草稿状态：本期不进入运行环境

问题：后端启动会把 `standards/` 下的包同步进数据库，默认启用。构件台账向导（`useStandardCatalogs` / `useSelectedPackage`）会列出所有启用的技术状况包，按包版本号从高到低排序后默认选第一个；评定树页也按“技术状况包”筛选。5230 包没有 H21 那套构件分类和台账模板，一旦以启用状态进库：

- 它会出现在台账向导的可选列表里，选了就生成不了台账；
- 默认选哪个是跨规范直接比版本号决定的。眼下 H21 1.0.4 排在 5230 1.0.0 前面只是碰巧，5230 包版本一旦超过 H21，就会变成默认选项。

做法：

- 清单 `status` 新增 `draft`（现只允许 `active`）。`technical-condition-package.schema.json` 和加载器同步放开。
- 运行时扫描遇到草稿包就跳过：不注册、不同步、不进规则管理，启动日志记一行“跳过草稿规则包”，不算加载失败。
- 测试和工具可以显式加载草稿包。
- 正式上线放到子项目 5：改为 `active`（摘要随之重算；草稿从未入库，不存在摘要冲突），同时让台账向导、评定树页按能力（是否带构件分类和台账模板、属于哪个评分体系）筛包，不再跨规范比版本号。

### 3.4 加载期内部校验

评分器构造前对包做一致性校验，不通过就拒绝创建评分器并报出具体位置：

- 每种评定类型的四个 γ 合计 1；每套权重在每个结构内合计 100；
- 部件 id、评定类型 id、单项控制 id 唯一；主要构件引用的部件存在；
- 分类界限连续、不重叠，覆盖 ECI 0～5 和 BSCI [0, 100]；
- 养护对策覆盖 1～5 类。

这些和校验能发现大部分录入笔误（漏行、错位、多打一位），但两个数互换发现不了，所以还需要 3.5 的人工核对。

原文无文字层，参数由我对着 PyMuPDF 渲染的页面图片逐表转录。每条数据带表号和页码。交付时附一份核对清单：按页列出表号、部件和数值，旁边放原文页面截图，由你抽查。测试里再按评定类型各抽一两个值写成断言，注明页码。

## 4 评分器

### 4.1 接口

- 新接口 `LayeredTechnicalConditionStandard : StandardAlgorithmAdapter`：`metadata()`、`validate(input)`、`evaluate(input) → outcome`、`explain(result)`。
- 实现类 `Jtg5230Evaluator`，在 `StandardRegistry` 里以 `jtg-t-5230-2026` 注册。
- 现有 `AssessmentService`、`AssessmentConfirmationService` 用 `dynamic_cast` 取 H21 的 `TechnicalConditionStandard`，取不到就判“阻断”，所以不会误用新评分器。H21 的接口与模型（`AssessmentModels.hpp`）不动，5230 的输入输出放在新文件 `Jtg5230Models.hpp`。
- 纯计算：不碰数据库、文件和时间；同样输入得到同样输出。

### 4.2 输入

本期输入直接给到构件的四项状态值；由病害推出这些值是子项目 4 的事。

```text
评定输入
  单元[]：单元 id、评定类型 id、权重套 id、桥跨 id 列表（按顺序）、全桥无须设置的部件 id 列表
  构件[]：构件 id、所属单元、部件 id、所属桥跨 id 列表（共用构件列多个）、
          EDDI（0～2 或空）、ESDI（0～3 或空）、EFI（0～2 或空）、EAI（−1～1 或空）、
          是否缺失（应设未设）、是否影响桥梁安全
  已触发的单项控制 id[]
```

单跨桥就是一个单元、一个桥跨。

### 4.3 计算步骤

1. 构件：EDI = 缺失 ? 3 : max(EDDI, ESDI)（空按 0）；非主要构件忽略 EAI；ECI = clamp(EDI + EFI + EAI, 0, 5)（下限见待确认 1）；查表得 ECL、状态词、养护对策。
2. 有效权重：取单元所选权重套；“全桥无须设置的部件”的权重按比例分给同结构其他部件（B.1.3）；权重套已显式给出的情形（如不设伸缩装置那一列）不再换算。
3. 桥跨：对单元内每一跨、每个部件，CI(j) = 该跨该部件所有构件 ECI 的最大值；该跨没有这个部件的构件则 CI(j) = 0。BSCI = 四舍五入到一位（100 − Σ CI(j)·ω·γ / 5），查表得 BSCL。四舍五入按十进制进行，不能受二进制浮点误差影响（例如 83.65 必须进为 83.7）。
4. 主要构件改判：该跨有主要构件 ECL ≥ 4 且标记“影响桥梁安全”时，若该构件等级比计算出的 BSCL 更差，则 BSCL 取该等级，BSCI 取该等级上限（4 类 60，5 类 40）；否则保留计算结果（见待确认 2）。
5. 单元：按 3.4.1～3.4.3 由各跨得出单元等级和指数（BCI 用已保留一位小数的 BSCI 计算，见待确认 3）。
6. 全桥：取最差单元（等级最差；同等级取指数较低者）；有单项控制被触发时，最终等级为 5 类，分层评定结果原样保留。

每一步写入计算轨迹（条文号、输入、输出），供日后的报告和界面说明使用。

### 4.4 输出

- 构件：EDI、ECI、ECL、状态词、养护对策；
- 桥跨：各部件的 CI(j)、有效 ω、γ、贡献值，BSCI、BSCL，是否被主要构件改判及依据构件；
- 单元：BCI、等级、采用的规则（单跨 / 等级一致 / 式 3.4.3）；
- 全桥：分层评定的 BCI 和等级、触发的单项控制、最终等级；
- 计算轨迹与一段中文说明。

### 4.5 输入校验（`validate`）

逐条报出，不抛异常：评定类型或权重套不存在；构件引用的部件不属于该评定类型；构件所属桥跨不在其单元内；标度越界；单元没有桥跨；单项控制 id 未知；同一构件 id 重复。只要有问题就不出结果。

## 5 测试

- 规则包：能按草稿加载，摘要正确；3.4 的各项一致性校验通过；按评定类型抽样核对原文数值（注明页码）。
- 加载器：`draft` 被运行时扫描跳过、显式加载可用；`active` 行为不变；其他状态仍报错。
- 评分器，逐条覆盖：
  - ECI 的上限 5 与下限 0；ECL 每一档；
  - BSCI 正好落在 90、75、60、40 上的分档；
  - 共用构件同时计入两跨；某跨缺某部件时 CI 取 0；全桥无须设置部件的权重重分；显式权重套不换算；
  - 主要构件改判生效与不生效；
  - 单跨、多跨等级一致、多跨等级不一致三条全桥规则；多单元取最差；单项控制触发；
  - `validate` 的每类错误。
- 手算算例，同时写进测试：

  两跨整体式板桥（表 B.2.2）。γ：桥面系 0.15，上部结构 0.40，下部结构 0.40，附属构造 0.05。

  - 第 1 跨：板 ECI 2，支座 1，桥面铺装 2，其余 0。Σ = 2×75×0.40 + 1×25×0.40 + 2×40×0.15 = 60 + 10 + 12 = 82，BSCI = 100 − 82/5 = 83.6，2 类。
  - 第 2 跨：板 1，桥面铺装 1，其余 0。Σ = 30 + 6 = 36，BSCI = 92.8，1 类。
  - 全桥：两跨等级不一致，取 2 类；平均 88.2；BCI = 83.6 + (90 − 83.6) × (88.2 − 83.6) / (92.8 − 83.6) = 83.6 + 3.2 = 86.8。

- 回归：后端全量测试保持通过，H21 相关测试不改。

## 7 待确认

1. **ECI 下限。** EDI、EFI 都为 0 而 EAI 为 −1（缺损趋向稳定）时算出 −1，表 3.2.6 从 0 起。建议按 0 处理，即 1 类。
2. **主要构件改判的生效方式。** 3.3.3 的“影响桥梁安全”需要人来判断，本期作为输入字段。建议只在构件等级比计算出的桥跨等级更差时改判，改判后指数取该等级上限（60 / 40）；计算出的等级已经同样差或更差时，保留计算结果。
3. **舍入顺序。** 建议 BSCI 先保留一位小数，再参与 BCI 计算（与人工按表计算一致）；分档也用保留后的值。
4. **单项控制与桥跨。** 3.4.5 条文说明写“将桥跨及桥梁技术状况等级评定为 5 类”，但条文没说是哪一跨。建议本期只把全桥定为 5 类，桥跨保留计算结果；后续录入时如能标注所在桥跨，再把该跨也定为 5 类。
5. **草稿状态。** 本期 5230 包不进规则管理，正式上线放在子项目 5。如果你希望现在就能在规则管理里看到它，需要同时改台账向导和评定树页的筛包逻辑，工作量会增加。
