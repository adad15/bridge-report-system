# 模块 06.5：以桥梁档案为中心的交互与界面重组

> 日期：2026-07-15
>
> 状态：已实施并通过回归验收
>
> 基线：模块 01～06 已完成；模块 05 校对工作台与模块 06 构件病害档案继续作为业务能力基础

## 1. 背景

当前系统按模块逐步生长，已经具备 Word 解析、年度事实校对入库、构件病害档案和跨年线索整理能力，但页面仍保留明显的开发阶段结构：

1. 系统首页只是后端健康状态，不能作为业务入口。
2. 桥梁详情把“年度检测任务”和“导入记录”分别平铺，用户需要理解数据库对象才能找到工作入口。
3. 年度、导入记录、校对工作台、构件档案之间缺少统一的桥梁上下文和返回路径。
4. 模块 05 全屏校对工作台功能完整，但入口像独立工具，校对完成后不容易回到对应年度。
5. 模块 06 的只读档案与“病害线索整理”分别暴露，业务上的主从关系不够明确。

模块 06.5 不重新发明模块 05、06 的业务功能，而是用一致的信息架构把它们组织为一条可理解的工作流程。

## 2. 已确认决策

1. 采用“桥梁档案模式”，不是全局任务流模式。
2. 打开系统首先显示桥梁档案列表。
3. 进入桥梁后默认显示“桥梁概览”。
4. 桥梁概览按“最新结论 → 待办事项 → 历年变化 → 病害概况”组织。
5. 年度检测采用“左侧年份列表 + 右侧年度工作台”。
6. 数据导入必须先进入具体桥梁和具体年度，不提供全局导入入口。
7. 当前仅实施 Word 一种导入格式，但界面使用“导入资料”“数据来源”等中性名称。
8. 现有模块 05 全宽校对工作台完整保留；年度工作台只负责显示摘要和进入校对。
9. 已确认导入继续通过同一校对工作台只读查看。
10. “病害线索整理”归入“构件病害档案”内作为待办功能，不再占用桥梁一级导航。
11. 多数据来源自动合并、冲突解决和来源优先级暂不实施；等第二种格式出现后再设计。

## 3. 目标

1. 用户不需要理解 `inspection_years`、`import_records` 等技术对象，也能完成“选桥 → 选年度 → 导入 → 校对 → 确认 → 查档”。
2. 所有页面清楚显示当前桥梁；年度相关页面同时显示当前年度。
3. 桥梁概览能在首屏回答“桥梁最新情况如何”和“现在有什么需要处理”。
4. 年度工作台成为年度资料、状态和动作的统一入口。
5. 复用模块 05、06 已验证的校对、只读、锁定、评分和档案能力，避免重复实现。
6. 页面命名不把系统永久绑定到 Word，但第一版不为未来格式提前建设合并框架。

## 4. 非目标

1. 不改变 `BridgeAnnualInspectionData` 1.2 合同。
2. 不修改病害、照片、评分校对规则和入库事务。
3. 不修改编辑锁、revision 竞态保护、重开校对和只读终态规则。
4. 不实现 Excel、PDF、CSV、JSON 或外部系统导入。
5. 不实现多个来源的自动合并、去重或冲突处理。
6. 不实现模块 07 的病害发展结论。
7. 不实现全局任务中心、桥梁资料管理、报告生成或新的权限体系。
8. 不为了界面重组迁移或复制既有正式事实。

线框稿中曾用于说明完整信息架构的“桥梁资料”“任务中心”等入口不进入本期可操作导航，避免出现空白或占位页面。

## 5. 用户与核心任务

第一版继续面向已登录的桥梁检测业务人员和管理员。

### 5.1 日常操作人员

- 从桥梁档案中查找目标桥梁；
- 查看最新年度结论和未完成事项；
- 新建年度检测并导入 Word；
- 进入全屏工作台校对病害、照片和评分；
- 查看已归档年度和构件病害档案；
- 整理尚未绑定的跨年病害线索。

### 5.2 管理员

在上述能力之外，继续使用模块 05 已有的管理员强制解锁和完整重开校对能力。本模块不改变管理员权限边界。

## 6. 总体信息架构

```text
系统
└─ 桥梁档案列表（系统默认页）
   └─ 绕阳河二号桥
      ├─ 桥梁概览（桥梁默认页）
      ├─ 年度检测
      │  ├─ 2026 年度工作台
      │  │  ├─ 导入资料：Word 报告
      │  │  └─ 全屏校对 / 只读查看
      │  ├─ 2025 年度工作台
      │  └─ 2024 年度工作台
      └─ 构件病害档案
         ├─ 构件只读档案
         └─ 待整理病害线索
```

核心对象层级为“桥梁 → 年度检测 → 数据来源”。导入记录是年度检测的数据来源和处理批次，不与年度检测并列。

## 7. 主流程

### 7.1 打开系统并查看桥梁

```text
登录成功
→ 桥梁档案列表
→ 按桥名、系统编号或路线搜索
→ 点击桥梁
→ 桥梁概览
```

根路由不再显示健康检查卡片。健康检查保留为开发/诊断能力，不作为普通业务首页。

### 7.2 新建并完成年度检测

```text
桥梁概览
→ 新建年度检测
→ 填写检测年度
→ 进入该年度工作台（等待导入）
→ 导入资料
→ 上传 Word 并解析
→ 进入全屏校对工作台
→ 保存草稿
→ 入库前检查
→ 确认年度事实入库
→ 返回该年度工作台（已归档）
```

同一桥梁同一年已有当前年度记录时，不静默新建重复年度。创建动作应引导用户进入现有年度；需要修订时继续使用模块 05 的显式修订流程。

### 7.3 查看已归档年度

```text
年度检测
→ 左侧选择 2025 年（已归档）
→ 右侧查看年度摘要和导入资料
→ 查看结果
→ 进入现有校对工作台只读态
→ 返回 2025 年度工作台
```

### 7.4 整理病害线索

```text
构件病害档案
→ 看到“7 条观测待整理”提示
→ 进入线索整理
→ 绑定已有线索 / 创建新线索 / 暂不确定
→ 返回构件病害档案
```

线索整理仍复用模块 06 现有页面和接口，只调整入口与返回位置。

## 8. 应用与桥梁导航

### 8.1 全局导航

第一版只保留真实可用的全局入口：

- 桥梁档案；
- 当前登录用户与退出。

“首页”和“桥梁列表”不再成为两个含义重叠的入口。根路由 `/` 跳转到 `/bridges`。

### 8.2 桥梁工作区外壳

普通桥梁页面共享 `BridgeWorkspaceShell`：

- 面包屑：桥梁档案 / 桥名 / 当前栏目；
- 桥梁标题：桥名、系统编号、路线、状态；
- 桥梁一级导航：桥梁概览 / 年度检测 / 构件病害档案；
- 主内容出口。

第一版不显示尚无业务页面的“桥梁资料”或独立“病害线索校对”标签。

模块 05 全屏校对路由不套入普通桥梁内容宽度，但页眉必须显示桥梁和年度上下文，并提供返回年度工作台的入口。

## 9. 页面设计

### 9.1 桥梁档案列表

列表至少显示：

- 系统编号；
- 桥名；
- 路线；
- 在役状态；
- 最新检测年度；
- 最新综合等级；
- 待处理数量。

支持在前端对已加载结果按桥名、系统编号和路线即时搜索。点击整行进入桥梁概览。第一版不增加复杂分页、组合筛选或收藏。

当没有桥梁、加载失败或搜索无结果时，分别显示明确空状态，不显示空白页面。

### 9.2 桥梁概览

默认信息顺序：

1. **桥梁身份区**：桥名、系统编号、路线、状态；右侧提供“新建年度检测”。
2. **最新年度结论**：最新当前有效年度、综合评分与等级、上部结构/下部结构/桥面系等已存在的评分摘要。
3. **待处理事项**：待校对导入、正在编辑提示、待绑定病害观测等；点击进入对应年度或线索整理页面。
4. **历年技术状况**：最近若干当前有效年度的等级、综合评分和状态。
5. **病害档案概况**：构件数、病害线索数、未绑定观测数和重点构件入口。

缺少某类正式评分时显示“—”，不得用候选值、旧修订版或虚构值填充。

### 9.3 年度检测工作台

采用左侧年份、右侧工作台布局。

左侧：

- 当前有效年度按年份倒序排列；
- 显示年份、年度状态、综合等级或待处理数；
- 默认选择 URL 指定年度；没有指定时选择最新年度；
- 切换年份更新 URL，刷新后保持选择。

右侧：

- 年度、状态、版本、创建/更新时间；
- 派生阶段条：已创建 / 已导入 / 校对中 / 入库检查 / 确认入库 / 已归档；
- “导入资料”列表；
- 病害、照片、评分和待处理数量摘要；
- 主要动作：导入资料、继续校对或查看结果。

阶段条是现有年度和导入状态的展示映射，不新增一套独立流程状态表。

### 9.4 导入资料

当前仅允许上传 `.docx`。界面文案使用：

- 按钮：“导入资料”；
- 类型：“Word 检查报告”；
- 卡片：“数据来源”或“导入资料”；
- 动作：“继续校对”或“查看结果”。

上传必须发生在已确定的桥梁和年度内。检测年度以当前年度工作台为准，沿用模块 04“系统输入为真源”的规则，Word 不自动决定年度，也不能把记录改挂到其他年度。

导入表单继续收集现有 Word 解析所需的业务输入：

- 来源类型：`软件导出Word` 或 `正式Word`；
- 规则模板：第一版固定为 `辽宁国省干线`；
- 检查日期；
- 报告编号；
- 项目名称。

“已有桥年度导入”“当前年度检测资料”“当前年度”等已由入口确定的技术参数由前端固定传递，不要求用户重复选择。

解析器对 Word 前部文本中的桥名执行现有校验：

- 识别到所选桥名：正常进入校对；
- 未识别到或不一致：在校对工作台明确显示 `bridge_check` 警告，但不自动换桥；
- 检测年度始终保持为当前年度工作台选中的年度。

第一版数据模型允许页面展示一个列表，但不实现多来源合并语义。

### 9.5 全屏校对工作台复用

现有 `ReviewWorkspacePage` 及其下列能力完整保留：

- 概览页眉和状态徽章；
- 编辑锁、心跳、失效保护和管理员强制解锁；
- 待处理项；
- 病害与照片校对；
- 技术状况评分校对；
- 原始 JSON；
- 来源证据；
- 保存草稿、批量确认、入库前检查和确认入库；
- 已确认、已取消和旧版终态只读；
- 修订重开和恢复。

本模块只对它做上下文集成：

1. 标题改为“{年度} 年度检测 · {来源类型}校对”；
2. 显示桥梁、年度和导入记录编号；
3. “返回桥梁详情”改为“返回 {年度} 年度工作台”；
4. 返回后保持原选中年度；
5. 校对页继续使用全屏工作台壳，不加入年度左侧栏。

年度工作台可以复用校对 API 的统计定义，但不能复制校对 reducer、锁状态机或确认逻辑。

### 9.6 构件病害档案

继续以模块 06 的左侧构件列表、右侧病害线索档案为主体。页面上方增加待整理观测摘要：

```text
有 7 条当前有效病害观测尚未整理到跨年病害线索  [进入线索整理]
```

点击后进入现有 `DefectThreadReviewPage`。该页面保留独立路由以支持刷新和浏览器前进后退，但不出现在桥梁一级导航。完成或取消后返回构件病害档案，并刷新未绑定数量。

## 10. 路由设计

```text
/                                      -> 重定向 /bridges
/bridges                               -> 桥梁档案列表
/bridges/:bridgeId                     -> 桥梁概览
/bridges/:bridgeId/inspections         -> 年度工作台，默认最新年度
/bridges/:bridgeId/inspections/:yearId -> 指定年度工作台
/bridges/:bridgeId/inspections/:yearId/imports/:importRecordId/review
                                       -> 现有全屏校对/只读工作台
/bridges/:bridgeId/components          -> 构件病害档案
/bridges/:bridgeId/components/:componentId
                                       -> 指定构件档案
/bridges/:bridgeId/defect-threads/review
                                       -> 线索整理任务页（非一级导航）
```

现有校对深链接保持兼容。`inspectionYearId=unassigned` 仅作为旧数据兼容路径，不作为新流程生成的正常 URL。

## 11. 后端和数据库边界

### 11.1 数据库

本模块原则上不新增业务表。继续读取和写入：

- `bridges`；
- `inspection_years`；
- `import_records`；
- 归档文件表；
- 当前有效年度事实表；
- `bridge_components`、`defect_threads` 和正式病害观测。

如现有唯一约束不足以防止同桥同年重复创建当前年度，应补充与现有 revision 设计一致的约束或事务检查，但不得破坏同桥同年修订能力。

### 11.2 查询接口

为避免前端拉取完整校对 JSON 只为显示几个数字，增加面向页面的只读摘要接口：

```http
GET /api/bridges/{bridge_id}/overview
GET /api/inspection-years/{inspection_year_id}/workspace
```

桥梁概览响应包含：桥梁摘要、最新当前有效年度评分、最近年度、待办计数、构件/线索/未绑定观测计数。

年度工作台响应包含：年度摘要、该年度导入资料摘要、候选统计、编辑锁摘要和可用动作。统计口径复用模块 05 的 `ReviewStatistics`，不在新路由中重写计算规则。

桥梁列表接口可扩展最新年度、等级和待办字段；旧字段保持兼容。

### 11.3 创建和上传接口

为完成界面主流程，需要补齐受控业务入口：

```http
POST /api/bridges/{bridge_id}/inspection-years
POST /api/inspection-years/{inspection_year_id}/import-records/word
```

第一个接口创建指定桥梁的年度检测；遇到同桥同年当前记录时返回稳定冲突码和现有年度 ID。

第二个接口接收 Word、创建导入记录、通过模块 02 文件归档边界保存原文件，并触发现有 C++ → Python Word 解析流程。不得让前端提供或读取服务器绝对路径。失败时保留可诊断状态，不产生半完成的正式年度事实。

现有 `POST /api/import-records/{id}/parse-word` 可作为内部复用步骤或保留的重试入口，不复制解析实现。

- `BridgeWorkspaceShell`：桥梁页眉、面包屑和一级导航；
- `BridgeOverviewPage`：桥梁概览；
- `InspectionWorkspacePage`：年份列表和年度工作台；

- `ImportSourceCard`：导入资料摘要；
- `InspectionProgress`：现有状态到展示阶段的纯映射；
- `CreateInspectionDialog`、`ImportWordDialog`：新建年度和上传 Word。

继续复用：

- `ReviewWorkspacePage` 及 `frontend/src/review/components/*`；
- `ComponentArchivePage`；
- `DefectThreadReviewPage`；
- 现有 API 客户端、认证上下文和编辑锁 API。

桥梁工作区外壳通过 React Router 嵌套路由或等价共享布局实现，不在每个页面复制桥梁标题和导航。

## 13. 状态、并发与错误

1. 年度工作台本身只读，不取得导入记录编辑锁。
2. 点击“继续校对”进入校对页后，才按模块 05 规则取得锁。
3. 若他人正在编辑，年度工作台显示“某某正在编辑”，进入后沿用现有只读/锁定提示。
4. 用户异常关闭校对页时，未保存修改丢失；锁按现有租约过期，不增加草稿自动恢复。
5. 页面请求失败必须显示错误和重试按钮，不能渲染空白页。
6. 当前选中的年度不存在、已删除或不属于当前桥梁时，显示明确错误并提供返回该桥梁年度列表的入口。
7. 创建、上传、解析均防止重复点击；进行中按钮禁用并显示进度。

## 14. 视觉与响应式原则

1. 普通桥梁页面使用统一的中性档案工作区，不再堆叠互不相关的大卡片。
2. 状态色仅用于状态和警告，不用构件类别色替代业务状态色。
3. 桌面端年度工作台保持左侧约 220～260px 年份栏，右侧弹性布局。
4. 小屏下年份栏改为顶部横向年份选择，内容区单列。
5. 全屏校对工作台继续遵循模块 05 已确认的固定页眉、侧栏、内容和底栏布局。
6. 空状态、加载状态、错误状态和只读状态都必须有文字说明与下一步入口。

## 15. 验收标准

### 15.1 导航

1. 登录后根路由进入桥梁档案列表，而不是健康检查页。
2. 点击桥梁进入桥梁概览，刷新后桥梁上下文不丢失。
3. 桥梁概览、年度检测、构件病害档案共享一致桥梁页眉和导航。
4. 病害线索整理不出现在一级导航，但可从构件病害档案进入并返回。

### 15.2 桥梁概览

1. 使用真实当前有效事实显示最新年度评分和等级；无数据时显示“—”。
2. 待校对导入和未绑定病害观测能够从待办直接进入对应页面。
3. 历年列表不混入旧修订版。

### 15.3 年度工作台

1. 年份倒序展示，默认选中最新年度；URL 可直接打开指定年度。
2. 导入资料按年度归组，不再在桥梁详情中跨年度平铺。
3. 待校对记录显示“继续校对”，终态记录显示“查看结果”。
4. 他人编辑时显示编辑人，不在年度页取得或抢占锁。
5. 退出校对工作台返回原年度，不返回旧桥梁详情卡片页。

### 15.4 新建和导入

1. 可以在桥梁内创建年度并上传 Word。
2. 同桥同年重复创建不会产生第二个当前年度。
3. Word 未识别到所选桥名时显示校对警告，且不会自动换桥；检测年度始终使用当前年度工作台的选择。
4. 上传文件通过后端受控归档，不暴露绝对路径。

### 15.5 回归

1. 模块 05 的编辑、锁定、保存、检查、确认、只读、重开和修订测试继续通过。
2. 模块 06 的构件档案和线索绑定测试继续通过。
3. Python Word 解析回归基线不变：25 条病害、31 个照片候选、36 个 Word 图片、31 张归档照片、15 个评分项。
4. 前端生产构建通过；新增路由和页面覆盖加载、空、错误、可编辑、只读和锁定状态测试。
5. C++/PostgreSQL 测试覆盖新增摘要、创建年度、Word 上传归档和重复创建事务。
