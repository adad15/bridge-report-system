# 评分表可选字段与 Python 错误反馈设计

## 背景

辽宁国省干线 Word 报告中的表 4.1-2 并不总是包含“构件数量”和“构件评分”两列。百股大桥 2024 年报告包含结构、类别、评价部件、部件评分、结构评分、权重、等级、全桥评分和综合评级，但缺少上述两列。现有解析器把全部 11 个表头都当作必需字段，因此将这张有效评分表误判为不存在。

同时，Python 解析服务已经返回结构化错误码和具体错误信息，但 C++ 后端将所有非 200 响应统一替换为 `python_parse_failed` 和“Word 解析服务未返回有效结果”，导致前端无法说明真实原因。

## 目标

1. 使用统一的表 4.1-2 解析逻辑，不区分 9 列版和 11 列版。
2. 将“构件数量”和“构件评分”作为可选字段；不存在时保持空白，交由用户后续手动填写。
3. 不使用 `0`、推算值或其他占位值填补 Word 中不存在的数据。
4. 将 Python 返回的业务错误传递到 C++、数据库和前端。
5. 保持连接失败、超时、非 JSON 响应等基础设施错误的统一兜底提示。

## 解析边界

表格标题仍须匹配辽宁规则中的“表 4.1-2 总体技术状况评定表”。以下核心表头必须存在：

- 结构
- 类别
- 评价部件
- 桥梁部件技术状况评分
- 桥梁结构技术状况评分
- 桥梁结构组成权重
- 等级
- 桥梁总体技术状况评分
- 综合评级

“构件数量”和“构件评分”为可选表头：

- 两列均存在时，按现有规则生成评价部件下的构件评分明细。
- 两列不存在时，正常生成评价部件、结构和全桥评分，构件评分明细为空。
- 只存在其中一列时，不尝试拼接不完整明细，构件评分明细保持为空，并生成一条待人工确认警告。

第二章病害检查表中的构件评分候选按现有独立流程继续解析，不依赖表 4.1-2 的可选列。

任何缺失值都表示“来源未提供”，不得写成 `0`。核心表头缺失、总分无法读取或没有任何有效评价部件时，仍视为解析失败。

## 数据流与错误处理

### Python

Python 对可识别但缺少可选列的表格返回成功响应。业务解析失败继续使用现有 FastAPI 结构：

```json
{
  "detail": {
    "code": "rating_table_not_found",
    "message": "未识别到辽宁国省干线表4.1-2总体技术状况评定表。"
  }
}
```

### C++ 后端

C++ 根据响应类型分流：

- Python 返回 200 且响应符合契约：继续现有入库流程。
- Python 返回 JSON 业务错误，且 `detail.code`、`detail.message` 有效：使用该错误码和信息标记导入记录解析失败，并以相同的 `{code, message}` 响应前端。
- 无法连接、超时、无响应、非 JSON 或错误结构无效：使用 `python_parse_failed` 和“Word 解析服务未返回有效结果”。

临时 Word 继续遵守既定生命周期：解析失败后保留 24 小时以便重试，不因错误透传改变清理规则。

### 前端

通用 API 客户端已经支持读取 `{code, message}`。导入弹窗应优先显示后端传回的 `ApiError.message`，而不是将所有解析错误重新映射成固定文案。

导入记录刷新后应显示数据库中保存的同一条具体错误，使错误信息不会随着弹窗关闭而丢失。

## 验收标准

1. 现有包含“构件数量”和“构件评分”的表 4.1-2 回归结果不变。
2. 百股大桥报告的表 4.1-2 可以成功解析：评价部件、结构和全桥评分有值，不存在的构件评分明细为空。
3. 缺少单个可选列时不伪造明细，并产生待人工确认警告。
4. 缺少核心字段的文档仍解析失败。
5. Python 返回 `rating_table_not_found` 时，C++ 响应、数据库错误字段和前端提示均保留具体错误信息。
6. Python 服务不可连接或返回非法内容时，前端仍显示基础设施兜底提示。
7. Python、C++ 路由和前端错误展示均有针对性自动化测试。

## 非目标

- 不新增“9 列版”“11 列版”等规则选项。
- 不自动推算 Word 中缺失的构件数量或构件评分。
- 不在本次修改中新增评分手动编辑页面；缺失项的后续人工填写沿用或留待校对功能继续完善。
- 不放宽表格标题和核心表头到任意相似表格，避免误识别附录或其他评分表。
