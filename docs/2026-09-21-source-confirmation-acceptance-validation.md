# 2026-09-21 来源数据库构件绑定与正式入库验收

## 结论与范围

2026 年度来源软件数据库已在隔离环境走通「完整台账 → 来源导入 → 构件绑定 → 病害校对 → 预检 → 正式事实入库」。使用程序现有绑定功能，没有新增全局名称替换规则。来源 SQLite 与原业务 PostgreSQL 没有写入；Word 文件导入路线继续暂缓。

本轮使用百股大桥真实来源数据与只读导出的已确认台账。隔离库 bridge_report_acceptance 位于私有 PostgreSQL 25432，C++ 28480、Python 28580、前端 25173。桥梁为隔离记录 QL-000004；本次导入 DRJL-000010，ID 6471db0e-8bf4-490a-af13-9ae5ad8a758f。此前三个年度的导入证据保留。

## 实际执行

1. 通过正常台账生成 API 复现 5,174 件台账，逐件核对编号、构件类型、规范类别与结构分部，全部一致；通过界面确认映射和台账。隔离版本 753835e7-998e-4b05-9189-e15d76ba3eb4，与业务台账 UUID 分离。
2. 使用当前前端和 source_db_importer 0.1.1，通过界面重新导入 2026 任务。得到 381 条来源病害、455 张病害照片，5 张任务概况照片不作为病害照片导入。
3. 自动绑定 327 个构件组；通过页面搜索并显式绑定 0#台盖梁→0#台帽、33#台盖梁→33#台帽、管养牌→照明、标志；选择两侧护栏→左侧栏杆与右侧栏杆；预览并展开两个 25 件板的范围。
4. 333 个构件组全部绑定，无缺失标记；生成 430 个活动实例，原始来源记录仍为 381 条。首次预检有 836 个阻断项，尚未校对的事实不能直接入库。
5. 页面批量确认 371 条。其余 10 条逐条打开精细维护：6 条来源为“其它病害”或“/”、内容为“基本完好”或“存在熏黑痕迹，已修补”，显式选择适用的既有不计分节点；4 条尺寸提示在保留来源结构化值及描述的前提下完成隔离复核。
6. 校对结果为 375 条已确认、6 条已修改、0 条待确认、0 条忽略，381 条均已完成组确认。末次预检无阻断；222 个非阻断提示包含 210 条未写详细位置、12 条非结构化尺寸原文保留。
7. 通过页面确认年度事实入库。程序在同一流程自动生成系统评定记录，本轮没有另做报告生成或发布。

上述名称绑定、不计分节点选择及尺寸冲突保留均为隔离验收选择，不是对实际桥梁现场状况或正式评定结论的认定。来源“4处裂缝”与数量列“1处”、描述与结构化长宽不一致等问题仍须业务人员核实；验收未把冲突值改写成推测值。两个范围照片提示仍保留。
