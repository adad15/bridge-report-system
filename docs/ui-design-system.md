# 桥梁检测报告系统 UI 设计规范

> 状态：当前 UI 基线，主要页面已实施
> 适用范围：`frontend/` 全部用户界面  
> 技术基线：React 18、TypeScript、Vite、Ant Design 6  
> 更新日期：2026-09-03

## 1. 文档目的

本规范是桥梁检测报告系统前端视觉与页面结构的单一事实来源。新增页面和逐步迁移的旧页面都应遵循本规范，避免不同模块各自定义颜色、间距、按钮、状态和页面骨架。

规范解决以下问题：

- 统一品牌、颜色、字体、间距、圆角和阴影。
- 统一登录页、管理列表、桥梁工作区和全屏工作台的页面结构。
- 统一表格、表单、状态、反馈、权限和危险操作的表达方式。
- 允许现有页面渐进迁移，不要求一次性重写全部前端。
- 通过 Ant Design Token 和共享布局将设计规则落实到代码，而不是依赖口头约定。

## 2. 核心原则

### 2.1 专业、清晰、克制

界面面向桥梁检测和报告编制人员，应优先保证信息准确、状态明确和操作可靠。视觉风格采用浅色工程管理台，不使用娱乐化插画、强烈霓虹色、厚重玻璃拟态或无业务意义的装饰。

### 2.2 内容优先

- 页面标题只说明当前任务，不重复展示无关品牌口号。
- 重要结论、待办和异常优先于装饰信息。
- 数据页面优先保证可扫描性，不为了“留白感”牺牲有效信息密度。
- 空状态必须说明原因和下一步，而不只显示“暂无数据”。

### 2.3 Token 优先

样式调整顺序必须是：

1. Ant Design 全局 Token。
2. Ant Design 组件 Token。
3. 组件公开的 `classNames`、`styles` 或业务容器样式。

禁止通过 `.ant-*` 选择器依赖 Ant Design 内部 DOM。禁止在业务页面中随意散落品牌色、状态色和通用间距的十六进制值。

### 2.4 页面级渐进迁移

- 以完整页面或完整对话框为迁移单位。
- 迁移时保留现有 API、状态管理和业务规则，只更换页面结构及表现层。
- 对应页面验收通过后，才删除其旧 CSS。
- 未迁移页面允许继续使用原实现，但不得反向影响已迁移页面的主题。

### 2.5 只用 Ant Design，不再新增自写 CSS

2026-09-14 起执行。系统里原有约 1.4 万行自写 CSS，与 Ant Design 并存导致同一类控件两套外观，也难以按屏幕尺寸统一调密度，因此逐步全部换成 Ant Design。

- 新写和改写的界面只用 Ant Design 组件及其属性表达：布局用 `Flex`、`Row`/`Col`、`Space`，文字用 `Typography`，弹窗用 `Modal`，表单用 `Form` 配 `Input`、`Select`、`InputNumber`、`DatePicker`，按钮用 `Button`，上传用 `Upload`，删除确认用 `Popconfirm` 或 `Modal`，错误和提示用 `Alert`。
- 不新增 `.css` 规则，也不为了样式新增 `className`。个别尺寸（固定高度、滚动区最大高度）通过组件的 `styles` / `style` 属性给出，只写尺寸，不写颜色、字号和间距——这些走主题 Token。
- 需要全站统一调整的视觉（控件高度、表单项间距等）改 `frontend/src/design-system/theme`，不在页面里覆盖。
- 旧 CSS 随页面迁移删除：一个选择器在代码里已经没有任何引用才删，仍有页面在用的先留着。
- 测试注意：Ant Design 会在两个汉字的按钮文字中间插空格（显示为「取 消」），测试里按名称找这类按钮写成 `/^取\s?消$/`；`Modal`、`Popconfirm` 渲染在 `body` 下的浮层里，用 `screen` 查询；`Dropdown` 的菜单项角色是 `menuitem`，要先点开触发按钮；`Select` 用 `src/test/antd.ts` 里的 `chooseOption`、`optionLabels`、`selectedLabel` 驱动和断言。
- 弹窗主体设了 `overflowY: "auto"` 时要同时写 `overflowX: "hidden"`，否则 `Row` 的负外边距会撑出横向滚动条。

迁移分五步，逐步验收：

1. 定下本条规矩；桥梁概况编辑弹窗、图件弹窗改为 Ant Design。（已完成）
2. 手写弹窗（`dialog-backdrop` / `workspace-dialog`）换 `Modal`，原生 `button`、`input`、`select`、`textarea` 换 Ant Design 对应组件。暂不含模块 06/07：`src/review/`、`src/triage/` 及其页面 `ReviewWorkspacePage`。（已完成：新建桥梁、新建年度、导入资料、三个删除弹窗、规范管理、重新绑定线索均已改为 `Modal`；自写的检查日期选择器换成 `DatePicker`；构件台账、台账向导、年度检测、构件列表、评定树搜索的表单控件已换。整行可点的列表项和树节点——评定树目录、构件分类、构件列表、工作台列表——仍是原生按钮，随第 4 步换成 `Tree` / `Menu` / `List` 时一起改。随之失去引用的约 180 条 CSS 规则已删除。）
3. 应用外壳（顶栏、侧栏）换 Ant Design `Layout`。（已完成：`Layout` / `Sider` / `Menu`，颜色与高度在 `design-system/theme` 的 `Layout`、`Menu` 组件 Token 里；顶栏 68px、侧栏 248 / 76px 的结构尺寸集中在 `AppLayout.tsx`。）

### 2.6 前后端权限一致

前端可以根据角色隐藏管理员入口，但不能把隐藏入口当作权限控制。路由、菜单和操作可见性必须与后端权限校验保持一致。

## 3. 前端设计系统结构

推荐逐步建立以下目录：

```text
frontend/src/
├─ design-system/
│  ├─ theme/
│  │  ├─ tokens.ts
│  │  ├─ componentTheme.ts
│  │  └─ index.ts
│  ├─ components/
│  │  ├─ PageHeader.tsx
│  │  ├─ StatusTag.tsx
│  │  ├─ MetricCard.tsx

│  │  └─ ConfirmActionDialog.tsx
│  ├─ patterns/
│  │  ├─ DataPageToolbar.tsx
│  │  ├─ DetailSection.tsx
│  │  └─ ErrorState.tsx
│  ├─ DesignSystemProvider.tsx
│  └─ index.ts
```

普通 `Button`、`Input`、`Card` 等组件直接使用 Ant Design，不为隐藏 Ant Design 而创建无业务价值的薄包装。只有包含稳定业务语义或重复交互规则的模式才封装，例如 `StatusTag`、`PageHeader`、危险操作确认框和数据页工具栏。

## 4. Provider 与主题基线

当前项目是客户端渲染应用，只设置一个根级 `ConfigProvider`。登录页和登录后的页面共用同一主题，不在页面内部嵌套新的全局主题 Provider。

全局 Provider 负责：

- 中文语言环境。
- 品牌主题 Token。
- 表单校验文案。
- 组件尺寸和圆角基线。
- 弹层挂载及消息类能力所需的统一上下文。

如未来改为 SSR，再单独评估样式注入顺序和 hydration；当前 CSR 阶段不增加 SSR 专用配置。

## 5. 视觉基础

### 5.1 品牌颜色

| 语义 | 建议值 | 用途 |
| --- | --- | --- |
| 主色 | `#3155D9` | 主按钮、选中项、链接、焦点 |
| 主色悬停 | `#2948BD` | 主操作悬停 |
| 主色浅背景 | `#EEF2FF` | 选中背景、轻提示、指标卡 |
| 页面背景 | `#F5F7FA` | 登录后应用背景 |
| 登录背景 | `#EEF3F8` | 登录页外层背景 |
| 容器背景 | `#FFFFFF` | 卡片、表格、弹窗、侧栏 |
| 一级文字 | `#1D2633` | 标题、主要数据、正文 |
| 二级文字 | `#667085` | 描述、辅助信息 |
| 弱化文字 | `#98A2B3` | 占位符、不可用信息 |
| 边框 | `#DCE3EC` | 输入框、卡片、分隔线 |
| 弱分隔线 | `#EAECF0` | 表格行、区域分隔 |

### 5.2 状态颜色

| 状态 | 前景色 | 浅背景 | 使用场景 |
| --- | --- | --- | --- |
| 成功 / 正常 | `#1F7A55` | `#EAF7F0` | 已完成、正常、已确认 |
| 进行中 / 信息 | `#3155D9` | `#EEF2FF` | 处理中、当前步骤、编辑中 |
| 警告 / 待办 | `#B26A00` | `#FFF4DD` | 待处理、需复核、锁定提醒 |
| 危险 / 失败 | `#C4323F` | `#FDEDEF` | 删除、失败、严重异常 |
| 中性 / 只读 | `#5F6B7A` | `#F1F3F5` | 已归档、停用、只读 |

状态不得只依靠颜色区分，必须同时显示文字、图标或形状中的至少一种。

### 5.3 字体

字体栈：

```text
"Microsoft YaHei", "Segoe UI", system-ui, sans-serif
```

| 层级 | 字号 | 字重 | 建议行高 |
| --- | --- | --- | --- |
| 页面标题 | 24px | 600 | 32px |
| 登录标题 | 28px | 600 | 38px |
| 区块标题 | 18px | 600 | 26px |
| 卡片标题 | 16px | 600 | 24px |
| 正文 | 14px | 400 | 22px |
| 表格正文 | 14px | 400 | 22px |
| 辅助文字 | 13px | 400 | 20px |
| 小标签 | 12px | 500 | 18px |

中文界面不使用强制大写或过宽字距。数字统计和编号应启用等宽数字，以便按位比较。

### 5.4 间距

采用 8px 基础网格，允许使用 4px 处理图标与文字等紧密关系。

| 级别 | 数值 | 示例 |
| --- | --- | --- |
| XS | 4px | 图标与文字 |
| S | 8px | 紧密控件、标签内部 |
| M | 16px | 表单字段、卡片内部元素 |
| L | 24px | 页面内容、区块之间 |
| XL | 32px | 页面边距、大区块 |
| XXL | 48px | 登录页和空状态的大留白 |

同一层级内优先使用固定间距，不依赖大量临时 `margin` 修补布局。

### 5.5 圆角与阴影

| 对象 | 圆角 |
| --- | --- |
| 输入框、按钮 | 8px |
| 普通卡片、表格容器 | 10px |
| 弹窗、抽屉内容 | 12px |
| 登录页主面板 | 24px |
| 标签、徽章 | 胶囊形或 6px |

普通内容卡片主要使用边框分层，不普遍使用大阴影。阴影仅用于登录主面板、弹窗、抽屉、下拉菜单和需要突出层级的重点卡片。

## 6. 页面骨架

系统只使用以下四类页面骨架。新页面必须先选择骨架，再组织内部内容。

### 6.1 `AuthLayout`：认证页面

用于登录、未来可能出现的密码修改或会话失效页面。

- 不显示后台顶栏和侧栏。
- 桌面端使用浅色双栏布局。
- 移动端隐藏左侧品牌视觉，保留单列表单。
- 表单区宽度保持 360–380px。
- 不展示不存在的“忘记密码”“注册”“第三方登录”等入口。

### 6.2 `ManagementPageLayout`：管理列表页面

用于桥梁档案、规范管理和其他数据管理页。

标准结构：

1. 面包屑。
2. 页面标题、说明和右侧主操作。
3. 可选统计卡或提示条。
4. 搜索、筛选、标签页和批量操作工具栏。
5. 表格或列表。
6. 分页。

页面内容区使用可用宽度，不再统一限制为窄幅居中卡片。

### 6.3 `WorkspaceLayout`：业务工作区

用于单座桥梁的概览、构件台账、年度检测和病害档案。

- 顶部全局栏展示系统级入口。
- 一级侧栏展示核心模块。
- 二级侧栏展示当前桥梁的工作区导航。
- 主内容顶部统一展示面包屑、桥梁名称、系统编号、状态和页面操作。
- 工作区中的多个页面共享桥梁上下文，不重复加载和重复展示相同信息。

### 6.4 `FullscreenWorkbenchLayout`：全屏工作台

用于 Word 校对、复杂绑定和其他需要多栏独立滚动的高密度任务。

- 保留最少量的全局导航。
- 页面自身占满剩余视口。
- 各面板独立滚动，避免整页滚动破坏工具栏位置。
- 固定操作区不能遮挡内容。
- 评定树可以采用同类全高双栏结构，但保留自己的树导航语义。

## 7. 全局应用结构

登录后的桌面端推荐结构：

```text
┌───────────────────────────────────────────────────────────────┐
│ 顶栏：品牌、全局搜索、帮助、通知、用户菜单                    │
├──────┬──────────────┬─────────────────────────────────────────┤
│ 一级 │ 二级上下文导航 │ 主内容区                                │
│ 导航 │              │                                         │
└──────┴──────────────┴─────────────────────────────────────────┘
```

建议尺寸：

- 顶栏：56px。
- 一级图标栏：64px。
- 二级导航：192px。
- 主内容页边距：24px；宽屏可增加到 32px。
- 表格工具栏和页面标题不因内容宽度变化而横向跳动。

一级导航只展示现有或已经确认建设的模块，不为了填满菜单虚构功能。桥梁内部导航必须与 React Router 路由保持一致。

## 8. 组件使用规范

### 8.1 按钮

- 每个独立区域最多一个主按钮。
- 主按钮用于当前页面最重要且安全的下一步。
- 普通操作使用默认按钮或文字按钮。
- 删除、永久清理等危险操作使用危险样式，并要求二次确认。
- 多个低频操作收进“更多”菜单。
- 禁用按钮应保留可理解的上下文；必要时通过附近文字说明禁用原因。
- 提交中使用加载状态并阻止重复提交。

### 8.2 表单

- 常规业务表单默认使用垂直标签布局。
- 标签使用真实字段名称，不把说明文字当作标签。
- 必填校验优先在提交时和离开字段时反馈，避免用户尚未输入就显示红色错误。
- 后端错误在表单顶部或相关字段附近显示，不能只用瞬时消息。
- 输入内容不得因请求失败而全部清空。
- 密码、令牌和其他敏感字段使用对应的安全输入组件。

### 8.3 表格

- 必须使用稳定且唯一的业务 ID 作为 `rowKey`。
- 搜索、筛选、排序和分页入口放在同一工具栏体系内。
- 数量和评分列右对齐并使用等宽数字。
- 主实体名称优先于内部 ID，内部编号作为次级信息。
- 不依赖“整行可点击”作为唯一入口，应提供明确的查看或进入操作。
- 批量操作仅在存在选中项时激活，并明确显示已选择数量。
- 大数据量时采用服务端分页；达到明显性能压力后再启用虚拟滚动。
- 远程搜索的选择控件应关闭本地重复过滤。

### 8.4 卡片

- 卡片用于表达一个完整信息单元，不用来包裹页面上的每一段内容。
- 指标卡必须有明确业务含义和可解释的数据来源。
- 轻渐变只用于少量重点指标，不同时让所有卡片争夺注意力。
- 同组卡片保持相同高度、内边距和标题位置。

### 8.5 标签与状态

- 统一由 `StatusTag` 映射业务状态与视觉语义。
- 相同状态在不同页面不得使用不同颜色。
- 待办数量使用徽标；实体状态使用标签；流程阶段使用步骤或进度表达。
- 状态文案优先使用业务语言，例如“待校对”“已确认”，避免只写“成功”“失败”。

### 8.6 弹窗与抽屉

- 简短确认和少量字段编辑使用弹窗。
- 复杂表单、详情预览和需要保留页面上下文的编辑使用抽屉。
- 弹窗标题必须说明对象和动作，例如“删除 2026 年度检测”。
- 危险确认必须展示影响范围，不能只问“确定吗”。
- 上传组件必须明确受控或非受控模式，并提供失败、重试和取消路径。

## 9. 登录页基线

登录页采用已经确认的浅色双栏方案。

### 9.1 桌面布局

- 页面背景：`#EEF3F8`。
- 主面板最大宽度：1120px。
- 主面板建议高度：640px，并适应较小视口。
- 左侧品牌区约 56%，右侧登录区约 44%。
- 左侧使用浅蓝到浅紫渐变、桥梁工程线稿和少量检测节点。
- 右侧表单宽度为 360–380px，垂直居中。

### 9.2 固定文案

- 产品名称：桥梁检测报告系统。
- 英文辅助：BRIDGE INSPECTION。
- 产品说明：公路桥梁定期检查、病害校对与报告编制平台。
- 表单标题：欢迎登录。
- 表单说明：登录桥梁检测报告编制平台。
- 安全提示：仅限获得授权的工作人员使用。

登录页不得展示默认账号、管理员能力说明或尚未实现的账号找回入口。

### 9.3 登录状态

| 状态 | 行为 |
| --- | --- |
| 初始 | 用户名自动聚焦；登录按钮禁用 |
| 可提交 | 用户名和密码均非空；登录按钮启用 |
| 登录中 | 输入框禁用；按钮显示加载状态；禁止重复提交 |
| 凭证错误 | 保留用户名；显示明确错误；焦点回到密码输入 |
| 服务异常 | 显示持久错误提示和可重试语义 |
| 大写锁定 | 在密码字段附近显示警告，不作为全局错误 |
| 登录成功 | 直接进入桥梁档案，不额外阻塞式提示 |
| 恢复会话 | 显示稳定的品牌加载状态，不闪现登录表单 |

## 10. 数据状态与反馈

每个数据页面必须明确覆盖以下状态：

- 首次加载：使用尺寸稳定的骨架或加载占位，避免布局跳动。
- 后台刷新：保留已有数据，只显示轻量刷新状态。
- 空数据：解释为什么为空，并在有权限时提供下一步操作。
- 搜索无结果：保留筛选条件，提供清除筛选入口。
- 请求失败：显示错误原因和重新加载入口。
- 部分失败：保留已成功内容，只标识失败区域。
- 只读：明确说明只读原因，不只把所有按钮变灰。
- 锁冲突：显示当前编辑者、锁状态和允许的下一步。

瞬时消息只用于无需后续处理的轻量成功反馈；需要用户理解或处理的问题必须留在页面中。

## 11. 权限与危险操作

- 管理员专属入口根据当前用户角色显示。
- 后端继续对每个受限接口执行权限校验。
- 破坏性操作不得作为默认主按钮。
- 删除桥梁、年度、导入记录前必须展示影响范围。
- 多对象删除需要显示对象数量和代表性名称。
- 操作完成后明确说明结果；涉及文件清理时说明是否可恢复。
- 审计原因等必填信息必须在提交前完成校验。

## 12. 响应式策略

本系统以桌面端为主，但基础页面应支持较窄视口。

| 视口 | 规则 |
| --- | --- |
| `>= 1440px` | 完整顶栏、一级栏、二级栏；内容边距 32px |
| `1200–1439px` | 完整导航；内容边距 24px |
| `768–1199px` | 二级导航可折叠；表格允许受控横向滚动 |
| `< 768px` | 单栏内容；侧栏通过抽屉进入；复杂工作台提示使用桌面端 |
| `< 480px` | 登录页取消外层大面板感，使用全屏单列表单 |

响应式不能通过缩小到难以阅读的字号解决。表格列应按优先级隐藏或改为详情入口，而不是无限压缩。

## 13. 可访问性

- 所有表单字段必须有可关联的标签。
- 图标按钮必须有可读名称。
- 所有交互元素必须支持键盘操作并显示清晰的 `focus-visible` 状态。
- 正文和背景对比度目标不低于 4.5:1。
- 状态不能只依靠颜色表达。
- 错误信息使用可被辅助技术感知的语义，并放在相关字段附近。
- 表格行点击不能取代行内明确链接或按钮。
- 动画尊重用户的减少动态效果设置，避免非必要的大幅位移。

## 14. 性能与稳定性

- Vite 构建使用具名导入，不在业务代码中一次性聚合所有 Ant Design 组件。
- 页面切换时保持稳定的外壳尺寸，避免页眉和内容横向跳动。
- 已有缓存数据应先展示，再进行后台刷新；显式写操作完成后丢弃相关缓存。
- 大表格优先服务端分页，避免一次渲染过多复杂单元格。
- 全屏工作台的面板独立滚动，并为 flex/grid 子项正确设置最小尺寸约束。
- 不为了视觉效果引入大尺寸背景图片；品牌线稿优先使用可控的 SVG 或 CSS 图形。

## 15. 迁移顺序

统一采用以下顺序：

1. 安装 Ant Design 6 和匹配版本的图标库。
2. 建立根级 `DesignSystemProvider` 和主题 Token。
3. 建立 `AuthLayout`，迁移登录页。
4. 建立 `AppLayout`，迁移顶栏、侧栏和用户菜单。
5. 迁移桥梁档案列表及其新增、删除流程。
6. 迁移桥梁概览。
7. 迁移构件台账。
8. 迁移年度检测。
9. 迁移构件病害档案和病害整理。
10. 最后迁移评定树和全屏校对工作台。

每一阶段独立验收，不以“大部分看起来正常”作为完成标准。

## 16. 页面验收清单

页面迁移完成前必须检查：

- [ ] 页面使用正确的四类骨架之一。
- [ ] 颜色、字号、圆角和间距来自主题或本规范。
- [ ] 页面没有新增 `.ant-*` 内部选择器覆盖。
- [ ] 主操作、次要操作和危险操作层级明确。
- [ ] 加载、空数据、无结果、失败和只读状态完整。
- [ ] 表单保留正确的自动完成、校验和提交中状态。
- [ ] 表格使用稳定 `rowKey`，搜索、筛选和分页入口统一。
- [ ] 管理员入口与路由、后端权限保持一致。
- [ ] 键盘操作、焦点样式和错误语义可用。
- [ ] 1366×768 和 1920×1080 下无非预期溢出。
- [ ] 登录等基础页面在 375px 宽度下仍可完成操作。
- [ ] 原有业务测试继续通过，并补充新增交互状态测试。
- [ ] 修改 Ant Design 代码后执行项目构建、相关测试和 Ant Design lint。

## 17. 规范变更规则

- 优先修改共享 Token 或共享模式，不在单个页面复制修复。
- 新增状态色、页面骨架或通用模式时，应同步更新本规范。
- 确有业务特殊性的页面可以例外，但应在代码中说明原因和边界。
- 评审页面时先判断是否符合本规范，再讨论局部视觉偏好。
- 本规范与已实现组件不一致时，应明确决定是更新规范还是迁移实现，不能长期维持两套事实来源。
